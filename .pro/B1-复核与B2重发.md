### 1.2 必修 M1：**1262 条孤儿证据**（`b15_repair.py` 没开 FK）

`b15_repair.py` 用 `sqlite3.connect(db)`，**没有** `PRAGMA foreign_keys=ON`（脚本第 5 行）。SQLite 默认 FK 关闭，所以：

```
DELETE FROM judgment WHERE subject LIKE 'file:"%'   → 删了 1262 条判断，但 evidence 没级联
```

实测（`.pro\out\b1_review.txt` R1）：**孤儿 evidence = 1262 行，全部 instrument=git**；`evidence` 总数 **5286**。

**纠正 flash 对 5286 的解释**（这是本轮唯一一处"把数字解释错了"）：

- 错："5286 比 4024 多 1262 = 重建的 1262 条 change 判断各带 1 条依据"。
- 对：重建的 1262 条判断确实各带 1 条新依据，但它们**替换的是被删那 1262 条的职责**，`kind=change` 的依据数仍是 **1921**（659 旧 + 1262 新，`b1_review.txt` R5）。多出来的 1262 是**没删掉的旧证据**，指向已经不存在的 judgment。
- 正确总数应是 **4024**（1971 tree-sitter + 1921 git + 122 docs + 10 issue）。

修复演练（`.pro\out\b1_fixdry.txt`，在 `.pro\tmp\b1fix` 的库副本上做，不碰 demo）：

```
DELETE FROM evidence WHERE NOT EXISTS (SELECT 1 FROM judgment j WHERE j.id = evidence.judgment_id);
→ rowcount=1262；judgment=4017、evidence=4024、孤儿=0、integrity_check=ok
→ evidence by instrument=[tree-sitter 1971, git 1921, docs 122, issue 10]
→ 抽样 ask：file:docs/MANIFEST-摘要.md=held、file:docs/README.md=held、issue:demo#2=held、decision:none=no_data
```

**为什么 `check` 没报**：`cmd_check` 只查两条（false_coverage / refuted_without_full），没有引用完整性检查（`main.rs:773-784`）。所以补一个 B1.6。

### 2.1 代码

`crates/datacore/src/store.rs`，在 `false_coverage`（现 448 行）**之前**加：

```rust
/// 指向不存在 judgment 的 evidence 行数（正常应为 0）。
/// 只可能来自"绕过本 crate 直接改库"（SQLite 默认 FK 关闭 → DELETE 不级联）。
pub fn orphan_evidence(&self) -> Result<i64> {
    let n: i64 = self.conn.query_row(
        "SELECT count(*) FROM evidence e
         LEFT JOIN judgment j ON j.id = e.judgment_id
         WHERE j.id IS NULL", [], |r| r.get(0))?;
    Ok(n)
}

/// 指向不存在 judgment 的 alternative_of 行数（正常应为 0）。
pub fn orphan_alternative(&self) -> Result<i64> {
    let n: i64 = self.conn.query_row(
        "SELECT count(*) FROM alternative_of a
         LEFT JOIN judgment j ON j.id = a.judgment_id
         LEFT JOIN judgment p ON p.id = a.parent_id
         WHERE j.id IS NULL OR p.id IS NULL", [], |r| r.get(0))?;
    Ok(n)
}
```
