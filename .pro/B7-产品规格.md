## 2. `explain`：修 3 个真 bug + 作者 + JSON

### 2.1 我自己在 demo 上跑出来的 bug（T1）

```
$ jw explain "crates/cli/src/cmd_clean.rs#cmd_scan" D:\projects\demo
  状态    held　[symbol:crates/cli/src/cmd_clean.rs#cmd_scan]
  改动    0 次          ← 应该是 1+ 次
  文档    无
  符号    0 个          ← 应该是该文件的符号数（>0）

$ jw explain "file:docs/README.md" D:\projects\demo
  改动    0 次          ← 应该是 3 次
  文档    无            ← 应该是 held（doc:docs/README.md）
```

根因（`main.rs:500-546`）：`cmd_explain` 用**原始输入**去查 `changes_for(path)`、`doc:{path}`、`count_symbols_for_path(path)`，但 `ask` 用的是 `resolve_subject()` 归一化后的 subject。所以带前缀或带 `#符号` 的输入，详情全查空。

### 2.2 改法

```rust
/// subject → 仓库相对路径：file:/doc: 去掉前缀；symbol: 取 # 前；其它原样。
fn subject_path(subject: &str) -> &str {
    if let Some(r) = subject.strip_prefix("file:") { return r; }
    if let Some(r) = subject.strip_prefix("doc:") { return r; }
    if let Some(r) = subject.strip_prefix("symbol:") {
        return r.rsplit_once('#').map(|(p, _)| p).unwrap_or(r);
    }
    subject
}
```

- `cmd_explain` 里所有"按路径查"的地方统一用 `let p = subject_path(&subject);`（`changes_for(p)`、`doc:{p}`、`count_symbols_for_path(p)`）。
- `resolve_subject`（`main.rs:480-496`）：
  - `input.contains(':')` 换成**前缀白名单**判断（`file:`/`doc:`/`symbol:`/`decision:`/`hypothesis:`/`issue:`），否则当路径；Windows 绝对路径（`C:\…`）不会被误当 subject；
  - 带 `#` 的输入**一律返回 `symbol:…`**（找不到也要返回 symbol，让 `ask` 如实报 `no_data`，不要 fallback 成 `file:path#name` 这种畸形 subject）。
- 新增"谁改的"：`store.top_authors_for_path(path, 2)`：
  ```sql
  SELECT author, count(*) n FROM change WHERE path=?1 GROUP BY author ORDER BY n DESC LIMIT 2
  ```
  输出一行：`作者    hp 14 次`（单作者时就是一行）。
- `--json`：`Explain { path, root, json: bool }`，`json` 时只输出一个对象（无彩色、无表头）：

```json
{"subject":"file:crates/cli/src/main.rs","path":"crates/cli/src/main.rs",
 "state":"held","reason":null,"changes":14,
 "last":[{"commit":"417009a1","status":"M","at":1792676803,"author":"hp","subject":"…"}],
 "doc":{"subject":"doc:…","verdict":"held"},"doc_present":false,
 "symbols":30,"authors":[{"name":"hp","changes":14}]}
```
> JSON 用 `serde_json`（把它加回 `crates/cli/Cargo.toml` 的 `[dependencies]`：`serde_json.workspace = true`）。这**不是新依赖**——同一 workspace 依赖、Cargo.lock 不变；手写转义是自找 bug。若你坚持零改动，就在 cli 里放一个 12 行的 `json_escape`，但我不建议。

### 2.3 验收（demo 真数据）

| 命令 | 期望 |
|---|---|
| `explain "docs/README.md"` | `改动 3 次`、`文档 held（doc:docs/README.md）`、`符号 0 个` |
| `explain "crates/cli/src/main.rs"` | `改动 14 次`、`符号 30 个`、`文档 无`、`作者 hp 14 次` |
| `explain "crates/cli/src/cmd_clean.rs#cmd_scan"` | `状态 held`、`改动 ≥1`、`符号 ≥1`（不再是 0） |
| `explain "nope/x.rs"` | `uncertain(no_data)`、`改动 0 次`，exit 2 |
| `explain "docs/README.md" --json` | 一行 JSON 可被 `serde_json` 解析，字段齐全 |

  2026-10-19  D-20261019-01、D-20261019-02

### 3.2 查询（只用现有表，不建新表）

```sql
-- 按天：提交 / 新增 / 改动 / 删除 / 当日触及文件
SELECT date(at,'unixepoch') d, count(DISTINCT commit_hash),
       sum(status='A'), sum(status NOT IN ('A','D')), sum(status='D'),
       count(DISTINCT path)
FROM change GROUP BY d ORDER BY d;
-- 每个文件首次出现（真·"从零"）
SELECT path, min(at) first FROM change GROUP BY path;
-- 决策按日期
SELECT date(at,'unixepoch') d, subject FROM judgment WHERE kind='decision' ORDER BY at;
-- 文档/符号按 mtime（诚实标注：不是历史）
SELECT date(at,'unixepoch') d, count(*) FROM judgment WHERE kind=? GROUP BY d;
```

新增只读方法（`store.rs`）：`change_days(limit)`, `file_first_days()`, `decisions_by_day()`, `judgments_by_day(kind)`；`collect::git::total_commits(root)` 用 `git rev-list --count HEAD`（无新依赖）。

### 3.3 边界（必须如实打出来，不许藏）

1. **`已扫描 < 仓库`**：demo 是 200 / 600 → 必须提示"历史不完整"，否则用户以为项目只有 3 天。顺手加 `ingest --limit 0` = 全量（`git log` 不带 `-n`）。
2. **决策日期早于首次提交**（10-19/20 vs 10-21）：照实显示，分组标注"可能早于提交窗口"。
3. **文档/符号没有历史**：它们的 `at` 是文件 mtime，只反映跑过 `docs`/`parse` 的那一批；单独一节标注"不是历史"。
4. 无 commit 的空库：打印"还没有提交"并 exit 2。

### 3.4 验收

`run.cmd timeline D:\projects\demo` 必须打出上面 **200/600、1921/147、三行日表 119/66/15、累计 96/143/147、11 条决策、doc 122/symbol 1971**；`--json` 可被解析。

## 4. `find`：按名字找东西

```
$ jw find cmd_scan
symbol   crates/cli/src/cmd_clean.rs:13  cmd_scan
file     crates/cli/src/cmd_clean.rs     held
```

- 输入：词（substring）；`--kind symbol|file|doc|decision`；`--limit N`（默认 20）。
- 命令名 `find`，保留 `search` 作别名（`#[command(alias = "search")]`），旧脚本不炸。
- 实现：复用 `search_subjects`（把内部 LIMIT 提到 100 再截断），按 subject 前缀分组：
  - `symbol:` → 取该判断的一条 `def:<path>:<line>:<kind>:<at>` 依据解析行号（`evidence_for`），拿不到就只打路径；
  - `file:`/`doc:` → 打路径 + verdict；
  - `decision:`/`hypothesis:` → 打 id + verdict。
- 行的顺序：symbol → file → doc → decision；同类按 subject 排序。
- 验收：`find cmd_scan` 出 1 条 symbol（行号 13）+ 0~1 条 file；`find README` 出 doc 与 file 若干；`find 不存在的词` exit 2。
