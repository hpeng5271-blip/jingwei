# 卡片族设计 v2：多卡 + 观测态 + 层级追溯 + 软启动（2026-10-25）

> 依据：用户第二轮口述（外部依赖分级、卡片信息预算、同风格多卡片、层层追溯、软启动）。
> 本稿只做评估与设计；不写代码、不动仓库。
> 数据口径：每条字段都标了来源；**库里没有的维度直接写"没有"，不设计假字段**。
> 现状基线（T1，今天实测）：`card` 输出 **4 行、最大行宽 71、填充率 1.04**（见 §2.4）——按本文判据它现在是"嘈杂"的，v1 要收。

---

## 0. 三句结论

1. **同风格多卡片**（5 种），不是"单卡多态"：范围不同 → 信息预算不同；单卡多态会把字段堆在一起，正是用户说的"堆砌"。
2. **每卡只给 1–2 个观测态**（文件卡 2 个，其余 1–2 个），不做"5 态 × 5 卡"的组合爆炸。
3. **v1（两周）只做 3 张卡**（文件/符号/改动，全是库内数据、零软启动）；模块卡、决策卡、依赖分级放 v1.5；大画布/LSP/机器底层不放 v1。

## 1. 卡片族（5 种）

统一骨架（学一次就够）：**标题行（范围+状态徽标）→ 内容行（≤5 字段）→ 依据 1 行 → 键位 1 行**。

| 卡 | 范围 | 观测态 | 信息预算 | 必须回答 | 出现 / 不出现 |
|---|---|---|---|---|---|
| **C1 文件卡** | 1 个文件 | `now`（默认）、`history`（按天改动） | ≤6 行 / 5 字段 / 依据 1 | ①现在还算数吗 ②最近谁在动它 | 有 `file:` 判断**或**磁盘上存在；目录 → 转 C4；跨模块 → 拒绝 |
| **C2 符号卡** | 1 个符号 | `def`（默认）、`dups`（多定义） | ≤5 行 / 4 字段 / 依据 1 | ①它是什么 ②定义在哪（几处） | `card <路径>#<名字>`；找不到 → 明说"未找到"，退回 C1 |
| **C3 改动卡** | 1 次提交 | `commit`（唯一） | ≤6 行 / 4 字段 / 依据 1 | ①改了什么 ②为什么（作者**声称**） | `card <hash>` 或从 C1 的"最近"进入；commit 不在库 → "未索引" |
| **C4 模块卡** | 1 个 crate/一级目录 | `overview`、`deps`（有 Cargo.toml 才出现） | ≤8 行 / 6 字段 / 依据 1 | ①多大 ②最近动哪 ③有没有外部依赖 | 恰好一个模块；仓库根/多模块 → "请用画布" |
| **C5 决策卡** | 1 条决策记录 | `summary`、`original`（软启动读原文） | ≤7 行 / 5 字段 / 依据 1 | ①为什么这么做 ②考虑过什么 | `card decision:…#…` 或从 C1/C4 的"决策"进入；无记录 → "无" |

### 1.1 每卡的真实样例（数据都来自 demo，T1）

**C1 文件卡**
```
┌ main.rs ──────────────────── held ┐
│ crates/cli/src/main.rs            │
│ 改动 14 · 最近 10-22 · hp         │
│ 符号 30 判断 / 31 定义            │
│ 依据 commit:417009a1              │
│ [t]历史 [s]符号 [d]决策 [q]关     │
└───────────────────────────────────┘
```
`history` 态（真实：10-21 有 9 次、10-22 有 5 次，首次出现 10-21）：
```
┌ main.rs · 历史 ───────────── held ┐
│ 10-21  +9 次改动（首次出现）      │
│ 10-22  +5 次                      │
│ 合计 14 次 / 2 天                 │
│ [n]回到现在                       │
└───────────────────────────────────┘
```

**C2 符号卡**
```
┌ cmd_scan ─────────────────── held ┐
│ fn · crates/cli/src/cmd_clean.rs  │
│ 定义 :13                          │
│ 依据 def:…:13:fn                  │
│ [f]文件 [c]改动 [q]关             │
└───────────────────────────────────┘
```
`dups` 态（真实：`main.rs#setup_console` 836/861 两处定义）：
```
┌ setup_console · 2 处定义 ── held ┐
│ :836   :861                       │
│ 判断是"至少存在一个"              │
│ [f]文件 [q]关                     │
└───────────────────────────────────┘
```

**C3 改动卡**
```
┌ 417009a1 ────────────── 10-22 hp ┐
│ jingwei data：数据台账先量后合    │
│ 21 文件（新增 1 / 改动 20）       │
│ 最大改动 crates/cli/src/cmd_data  │
│ 依据 commit:417009a1              │
│ [f]看文件 [q]关                   │
└───────────────────────────────────┘
```
> `subject` 只是**作者声称**（commit message 可能说谎，DESIGN-AUDIT D1）；卡上不写"原因"，只写"声称"。

**C4 模块卡**（v1.5）
```
┌ crates/cli ───────────────── held ┐
│ 文件 27 · 符号 366 定义           │
│ 最近 10-22 · hp                   │
│ 决策 2                            │
│ 依赖 3：内部 1 · 第三方 2         │
│   anyhow · serde_json             │
│ [d]依赖 [f]文件 [q]关             │
└───────────────────────────────────┘
```
真实数据：27 个文件、366 处符号定义、2 条决策提到该路径、`Cargo.toml` 里 `anyhow`/`serde_json`（第三方）+ `jingwei-engine`（path，内部）。

**C5 决策卡**（v1.5）
```
┌ D-20261021-05 ────────────── held ┐
│ 候选 3 条（1 选中 / 2 否决）      │
│ 依据 record:D-20261021-05         │
│ [o]读原文 [a]候选 [q]关           │
└───────────────────────────────────┘
```
> **标题不在库里**：decision 判断只存了 `record:<id>` 指针（依据），原文在 `docs/decisions/<id>.md`。所以"标题/决策句"必须**软启动读文件**（§4），摘要态不显示标题——这是诚实，不是缺字段。

## 2. 密度判据（可判，不是形容词）

### 2.1 硬预算

| 项 | 线 |
|---|---|
| 卡宽 `W` | 48 列（终端 ≥100 列）；80 列终端用 44 |
| 行数 | C1 ≤6、C2 ≤5、C3 ≤6、C4 ≤8、C5 ≤7（含边框） |
| 字段行 | ≤5（C4 ≤6）；依据 ≤1 行；键位 1 行 |
| 每卡问题数 | **≥1、≤2**；第 3 个问题必须换卡 |
| 样式种类 | ≤3（状态徽标 / 强调 / 依据） |
| 每行强调 | ≤1 处 |
| 依据行 | 超 `W-2` 截断加 `…`，全文只在展开态 |

### 2.2 填充率 ρ（把"嘈杂/饥饿"变成数）

```
ρ = 内容显示宽度（不含边框）/（内容行数 × W）
  · 中文按 2 列宽计
健康：0.45 ≤ ρ ≤ 0.75
饥饿：ρ < 0.45   → 合并字段，或降到更小范围（文件→符号），或干脆不单开卡
嘈杂：ρ > 0.75   → 拆观测态（把历史/依赖/候选挪到展开态）或截断
```

### 2.3 两个反例（按本判据）

- **嘈杂**：把"历史/依赖/候选"全塞进一张卡 → 行数 >8 或 ρ >0.75；用户会找不到重点。
- **饥饿**：只显示"路径 + 状态"两行（ρ≈0.25）→ 不如放进状态栏/文件树，单开卡是浪费。

### 2.4 现状实测（T1）

当前 `card crates/cli/src/main.rs`：**4 行、最大行宽 71、ρ = 1.04** → 按 2.2 判为**嘈杂**（超宽且过密）。v1 必须收到 `W=48`、拆出 `history` 态，才能进健康区。
（这也回答"能不能容纳更多信息"：**不能靠加宽/加行**，只能靠**分态**。）

## 3. 层级与追溯

### 3.1 层模型

```
L0 文件 ─► L0.5 符号/定义 ─► L1 多文件（同模块，2–3 张） ─► L2 模块 ─► L3 项目（画布） ─► L4 机器层
```

| 层 | 卡 | 范围 | 禁止 | 数据 |
|---|---|---|---|---|
| L0 | C1 | 1 文件 | 跨文件 | 库内全有 |
| L0.5 | C2 | 1 符号（可多定义） | 引用/调用者 | 库内：定义行号在 evidence |
| L1 | C1×2–3 | 同模块多文件并置 | 跨模块；>3 张 | 库内 |
| L2 | C4 | 1 模块 | 列全部文件（≤5 + "还有 N 个"） | 库内 + Cargo.toml |
| L3 | 画布（v2 外） | 全项目 | 细读 | 库内 |
| **L4 机器层** | 文件系统节 | 单文件 size/mtime/只读 | **CPU/进程/磁盘 IO** | 只能软启动 `stat`；**运行时采集模型明确不做** |

**"计算机底层"的边界**：用户说"到计算机底层"。我们能做到的是**文件系统层**（大小、mtime、只读位、行数），这部分有数据（`stat` 一次调用）。**CPU/内存/进程/磁盘 IO 没有数据，也不该在 v1 假装有**——那是运行时采集，模型早就划掉了。

### 3.2 每卡状态机

```
S0 摘要 ──Enter/点击可展开行──► S1 展开一节 ──点击依据/引用──► S2 追溯（跳到另一张卡）
  ▲                                  │                              │
  └──────────── Esc（收一层）─────────┴────────── b（面包屑回退）───┘
q = 关闭；t/s/d = 换观测态（不离开当前卡）
```

- **S1 只展开一节**（依据 / 历史 / 依赖 / 候选），避免"全展开=堆砌"。
- **S2 焦点唯一**：同一时间只有一张卡在 S2；跳到另一张卡时，原卡回 S0。
- **面包屑**：`file:main.rs › symbol:cmd_scan › def:cmd_clean.rs:13`；每退一层缩短。
- **不可逆规则**：L0 不能直接跳 L3；跨模块只能从画布进；L4 只能从 C1 的"磁盘"节进（软启动）。
- 每层显示什么（对应数据）：

| 节 | 显示 | 数据来源 |
|---|---|---|
| 依据 | 1–2 条 premise（commit/def/doc/record） | `evidence_for` |
| 历史 | 按天改动次数、首次出现日 | `change` 表 |
| 符号 | 符号清单（≤5 + N）、kind 分布 | `judgment` + `def:` premise |
| 依赖 | 直接依赖名、内/外分类、传递计数 | Cargo.toml / Cargo.lock（软启动） |
| 候选 | hypothesis 列表（≤3 + N） | `alternative_of` |
| 磁盘 | size、mtime、只读位 | `stat`（软启动） |

### 3.3 "软启动"定义（懒计算）

| 项 | 规则 |
|---|---|
| 触发 | 只在 S1 展开**库外数据**的节：①`stat`（size/mtime/只读）②Cargo.toml 依赖 ③决策原文（标题/决策句） |
| 预算 | `stat` ≤10ms；Cargo.toml ≤50ms；md 读 ≤20ms；**单次展开总 ≤100ms** |
| 缓存 | 进程内按 `(path, mtime)`；**不写库**（不建新表） |
| 超时/失败 | 显示 `未采集：<原因>`（文件不存在 / 无权限 / 超时>100ms / 解析失败），**只显示一次、不重试** |
| 禁止 | 无超时的"计算中…"占位；用软启动数据阻塞摘要行；把软启动结果写进判断/证据 |
| 与判断的关系 | 软启动数据**不进 judgment/evidence**（它不是观测，只是显示辅助）；卡片上标 `src=fs/cargo/md` |

## 4. 外部依赖分级

**裁决：v1.5 做，v1 不做。** 理由：v1 的三张卡（文件/符号/改动）不涉及依赖；依赖只在模块卡（C4）出现，而 C4 已在 v1.5。**不为了赶 v1 硬塞一个解析器。**

### 4.1 数据来源与解析（无新依赖）

- `Cargo.toml`：手写扫描，只认 `[dependencies]`、`[dev-dependencies]`、`[workspace.dependencies]` 与 `[dependencies.NAME]` 子表；取 `=`/`.` 左边的名字；忽略值/features/注释；**不做 TOML 语义解析**（风险：多行表/内联表会漏，但不会编）。
- `Cargo.lock`：数 `[[package]]` 段 = 直接+传递总数（不建映射）。
- 判定不了就**不显示**，不猜。

### 4.2 分级模型

| 档 | 判定 | 卡上显示 |
|---|---|---|
| 内部 | path 依赖 / workspace 成员 | `内部 n` |
| 第三方直接 | 出现在 `[dependencies]`/`[dev-dependencies]` 且不是内部 | `第三方 n` + 名字（≤3 + "还有 N"） |
| 传递 | `Cargo.lock` 包数 − 直接 − 内部 | `传递 m（未分级）` |
| 风险 | **没有漏洞库/许可证数据、不联网** | **不显示**（如必须占位，只写 `风险 未评估`，禁止出现"安全/不安全"） |

### 4.3 显示规则

- **没有依赖 → 整节省略**（用户原话：外部依赖没有不显示）。
- 有依赖 → 只占 1–2 行（依赖数 + 分类 + 至多 3 个名字）；完整清单在 S1 展开。
- 真实样例：`crates/cli` → `依赖 3：内部 1 · 第三方 2`，名字 `anyhow`、`serde_json`（内部 `jingwei-engine` 不列名字，只计数）。

### 4.4 何时做完整版（传递树 + 风险）

等**有漏洞库/许可证清单**（离线数据也行）时再做；否则风险档只能是"未评估"，做了也是摆设。

## 5. 布局

### 5.1 终端能做什么

- **单卡**：`jw card …` 一屏一张（默认）。**做不到"不占视野的角落"**——终端没有浮层；只能由用户用 tmux/分屏把卡片放边上。
- **两卡并排**：`W=48` 时两卡 = 96 列，只在 ≥100 列终端可行；由用户分栏，不由我们排版。
- **三卡以上**：不做（等于把终端变画布，且没有焦点管理）。

### 5.2 编辑器能做什么（v2 插件）

- 侧栏/浮动卡片：能贴角落、跟随光标、按选区过滤；这是"不占视野"的**唯一真解**。
- 但每个编辑器各写一份（VS Code / RustRover），v1 不做。

### 5.3 多卡布局草图（终端 + 编辑器并排）

```
┌─ 编辑器 ────────────────────────┬─ 卡片列（≤40% 宽）──┐
│ fn main() {                     │ ┌ main.rs ── held ┐ │
│     …                           │ │ 改动 14 · hp    │ │
│                                 │ └─────────────────┘ │
│                                 │ ┌ 417009a1 ───────┐ │
│                                 │ │ 21 文件         │ │
│                                 │ └─────────────────┘ │
└─────────────────────────────────┴─────────────────────┘
```
规则：卡片列 ≤ 屏宽 40%（编辑器 ≥60%）；卡片数 ≤2；第三张必须替换或收起。

## 6. 取舍（v1 两周）

### 6.1 v1 做（3 张卡、4 个态）

| 卡 | 态 | 数据 | 为什么现在能做 |
|---|---|---|---|
| C1 文件卡 | `now` / `history` | `ask` + `change` + `judgment` + `doc` | 全在库里；`history` 只是 `change` 按天聚合 |
| C2 符号卡 | `def` / `dups` | symbol 判断 + `def:` 依据 | 行号可从依据解析（已有 `find` 在用） |
| C3 改动卡 | `commit` | `change` 按 commit 聚合 | 一次 SQL；21 文件是实测 |

**v1 不做软启动**（三张卡全库内数据），所以没有超时/缓存问题；先把"密度 + 分态"跑对。

### 6.2 v1.5 做

C4 模块卡（含依赖分级）、C5 决策卡（含读原文软启动）、文件大小/mtime/只读的"磁盘"节、`--json` 扩展。

### 6.3 推迟

大画布、图标体系、多卡联动/同步滚动、LSP 客户端、符号依赖图（无 edge 数据）、时间轴动画、跨模块卡片、传递依赖树、风险档。

### 6.4 永远不做

- **单页全包**（用户两次否掉，且与"变换自由度"冲突）；
- **没有数据的占位**（"计算中…"到死、"无依赖"空行、"安全"等无据结论）；
- **假图**（没有 edge 数据却画调用图）；
- **自动语义摘要**（会引入"猜"）；
- **把软启动数据写进判断/证据**。

## 7. 与现有命令的关系

- `card` 已存在（4 行）；v1 是**重排**它（48 列、分态、依据截断），不是新命令。
- `explain --json` = C1 的数据契约（已实现，字段够：state/subject/changes/recent/doc/symbols/authors/evidence）。
- `timeline` = 时间态的数据底座（已实现，600/200、1921/147 实测）。
- `find` = C2 的入口（已实现，`cmd_scan` → `cmd_clean.rs:13`）。
- 缺口仍是 §1.4（无 edge、无依赖解析、无历史）；本设计**没有**给缺口编字段。
