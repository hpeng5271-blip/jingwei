# 断言行文法与判据（checker 未建，先定契约）

> 版本 v1（2026-10-25）。这份是**将来 checker 与 `record`/人工共用的契约**；现在不实现 checker。
> 相关实验：E4 v1（句子分类）、E4 v2（断言行扫描）。落点：`.pro\out\e4.txt`、`.pro\out\e4_v2.txt`。

## 1. 行格式（只此一种，别扩）

```
- 断言: <type> <arg>
```

- `type ∈ { path_exist, path_absent, symbol_exist }`
- 一条一行；`断言:` 后是**半角空格**再 `<type>`；行尾**不许**跟解释/标点。
- 缩进：顶层 `- `（两个字符），不嵌在列表里。
- 解析器容忍全角冒号 `断言：`，但**模板固定写半角**（`断言:`）。
- `<arg>` 不许含空白。路径一律**仓库相对 + 正斜杠**；不许绝对路径、不许 `..`、不许盘符。

### 类型与参数

| type | arg | 语义（一句） |
|---|---|---|
| `path_exist` | `<repo 相对路径>` | 该路径存在且是文件 |
| `path_absent` | `<repo 相对路径>` | 该路径不存在（不区分"没有这个文件"还是"没有这个目录"） |
| `symbol_exist` | `<repo 相对路径>#<符号名>` | 该文件里 tree-sitter 能找到一个名为 `<符号名>` 的定义 |

`symbol_exist` 用已有实现判定：`collect::parse::file_symbols(路径)` 里 `any(|s| s.name == 名字)`——与 `verify` 同一套，不另写。

## 2. 判定表（true / falsified / 查不了）

| type | true（supports） | **falsified**（contradicts） | **查不了**（unknown，不算 falsified） |
|---|---|---|---|
| `path_exist` | `root.join(p).is_file()` | 不存在 / 不是文件（是目录） | arg 格式错（绝对路径、含 `..`、空）；`metadata` 无权限读 |
| `path_absent` | 不存在 | 存在（文件或目录） | arg 格式错 |
| `symbol_exist` | 文件在 + 解析成功 + 找到名字 | 文件在 + 解析成功 + **没找到名字**；**或文件不存在** | 文件在但读失败 / tree-sitter 解析失败；arg 格式错（缺 `#`、名字空） |

**`symbol_exist` + 文件不存在 = falsified，不是查不了。** 理由：
1. 断言是"**这个文件里**有这个名字"，文件都不在时命题确定为假；
2. 若判"查不了"，当记录里没有配套的 `path_exist` 时，文件被删这件事**完全不会**被任何断言抓住——那 checker 就漏了最该抓的漂移；
3. 与 `path_exist` 同路径时一次根因产生两条 falsified，是**观测冗余**，不是矛盾：每条断言各自记账，聚合时按"任一条 falsified"处理即可。

**查不了只留三种**：参数格式错、文件读不了、tree-sitter 解析失败。除此之外一律给确定结论。

## 3. 与 `record`、judgment、scope/evidence 的关系（现在就这样定）

| 问题 | 裁决 | 理由 |
|---|---|---|
| `record` 要不要解析断言？ | **不要**。模板迁就现有 `record` 解析：断言段是普通 `## 断言` 章节，`- 断言: …` 是普通 bullet，不在替代项章节里，所以 `record` 根本不会读它 | 本批不改 `record` 行为（用户约束）；断言是"待核对命题"，不是要落库的观测 |
| 断言进 scope 吗？ | **不进** | scope.objects 是"判断覆盖的实体"，断言是"待核对的主张"；混在一起就是 D-21 的错误（同一字段两种语义） |
| 断言进 evidence 吗？ | **不进** | evidence 是观测；断言还没有观测者。E1 已证明"把文本当证据"判别力 0 |
| 断言进 judgment 吗？ | **不进** | 同上；将来由 checker 产 `claim` 判断（A2 留的概念位置），断言只是输入 |
| 那 checker 将来怎么记？ | 每条断言 → 一条 evidence（`instrument=checker`，premise=`check:<记录 id>:<序号>:<type>`，极性随 true/falsified）；coverage = `已核对/断言总数`；`查不了` 计入 total 不计入 read | 与现有 coverage 语义一致：覆盖不足 → `uncertain(coverage_short)` |
| record 的 verdict 会因断言改变吗？ | **不会**。`decision.verdict` 仍只表示"决策状态"，断言结果落 `claim` | A2 的读法规则：不同 kind 的 verdict 不跨读 |

## 4. 开 checker 的两个门槛（数字来自 E4 v2）

1. `importable_assertions ≥ 1`，且其中 `path_absent`/`symbol_exist`（可能不成立的类型）≥ 1；
2. 对那条记录做一次**干跑**（脚本按上表判，不写库），`unverifiable = 0`——只要有一条查不了，先修文法/参数/观测能力，不开 checker。

两条都满足，才允许写 `claim` kind + checker。**falsified 不要求 ≥1**：记录写对时断言应当全真；checker 的价值在**以后**代码漂移时把 true 翻成 falsified。要求"开局就 falsified"会鼓励写错记录。
