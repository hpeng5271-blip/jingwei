# 经纬

终端和 IDE 之间的**理解层**。它不替你写代码，也不替你装环境；它只做一件事：
把「这个项目现在到底是什么状态」讲清楚，并且**在你需要的时候才讲**。

## 它填的是哪个空档

新手卡住的地方，通常不是"不会写代码"，而是这些：

- 这台机器上装了哪些工具链，哪个版本，够不够用——没人告诉他，他也不知道去哪查。
- 项目拉下来跑不起来，报错一屏，**先修哪一个**没有头绪。
- 改了代码，说不出"改动了什么、影响了什么"。
- 环境越装越乱，磁盘越来越满，**不敢删也不知道能删什么**。
- 做了两天，说不清"我到底做了什么、学到了什么"。

IDE 和终端不是不会这些，是它们**不负责筛**：所有信息一律平铺，新手只能被淹没。
经纬的全部价值就是这里的两个字——**过滤**，和它后面必须跟着的**反馈**。

## 四条不许破的线

这四条写进代码（类型、构造入口、断言），不是写在文档里靠自觉：

1. **数据正确优先**于速度、先于延迟、先于首次加载体验。
2. **不生成修复命令**——告我症结与该点哪里看，不要替我动手，更不要给我一句我不懂的咒语。
3. **没有自查命令，不许报 Error**。查不了 ≠ 没问题，这两个状态必须分得开。
4. **每条关系都必须有来源**。查不到来源的推断，不出结论。

## 界面上的七个页面

选中项目后：**概览**（结论与待处理项）· **运行**（装依赖 / 构建 / 测试 / 运行）·
**编辑器**（改动先进草稿，应用才落盘）· **记录**（笔记 / 运行日志 / 变更）·
**图谱**（这个项目里有什么、连着什么，按角色分环）。
不依赖项目也能单独用：**机器清单**（这台机器有什么、哪里不对）· **清理**（能删的 / 要权限的 / 别碰的）。


## 目录结构（crate 边界就是架构）

```
crates/model     领域模型：实体、关系、来源、置信度、结论。零依赖（只有 serde）。
crates/engine    全部逻辑。不依赖任何 GUI，对外只给 JSON。
                 分六层（util / sys / detect / understand / graph / state）+ launch 编排；
                 一条龙的前四个阶段按语言分家（launch/python.rs · node.rs · java.rs），
                 后两个阶段（拉起进程、等待就绪）三种语言共用 launch.rs 里那一处实现。
crates/cli       命令行外壳：只负责排版和参数解析。命令按领域分成七个文件
                 （cmd_machine / cmd_doctor / cmd_project / cmd_run / cmd_clean /
                 cmd_graph / cmd_guide）。**数一遍再写**：这里原来写"六个"只列了五个，
                 图页与指南那两个命令不在名单里（2026-10-17 数出来的）。
src-tauri        桌面外壳：只做展示和转接，逻辑一个都不重复。
                 payload.rs 专门负责"一次体检的全部材料"打包成前端能直接用的形状。
ui               前端（静态页面，无打包器）。按一屏/一域拆成 7 个经典脚本，
                 加载顺序写在 index.html 里——`const` 不会提升，顺序是硬约束。
tools            门禁与探针脚本（gates.json 是门禁清单的唯一真源）。
```

依赖方向单向：`cli` / `src-tauri` → `engine` → `model`。反方向引用会被架构本身挡住。

## 构建与运行

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\gates.ps1
```

一条命令跑完四道门禁（单测+集成（含文档测试） / 静态检查 / 真源门禁 / 交付门禁），
每道写清它守着什么、失败给原始输出、结束给一张表。清单的唯一真源是
`tools/gates.json`——**改门禁只改那一份**，脚本只负责跑。
想单独跑哪一道，`tools/gates.json` 里每一行都写着原命令。

**这四道目前没有跑在 CI 上**（仓库里没有 `.github`）。这条以前在《设计》里
被写成了"跑在 CI 上"，那是一句没人兑现的话——现在如实说明，理由见 [设计.md](docs/design/设计.md) §12.3。

只做命令行版：`cargo build --release -p jingwei`。
带界面：`npx tauri dev`（要 Node 与 WebView2，Windows 自带）。
打包成绿色压缩包：`powershell -File pack.ps1`。

## 名字与数据放在哪

面向人的名字是**经纬**，面向机器的标识是 `jingwei`（crate 名、可执行文件名、数据目录）。
工具在每个项目里只留一个目录：`.jingwei/`——笔记、草稿、运行记录、变更基线都在里面，
跟着项目走，随时可删（删了不影响项目本身跑起来）。

改过两次名，旧目录会**自动搬过来**：`.pylaunch` → `.drydock` → `.jingwei`。
这条迁移链只许往后加，不许删。

一条龙认语言了：Python / Node / JVM 各自按自己的方式检查环境、解析依赖、挑启动命令，
后两个阶段（拉起进程、等待就绪）三种语言共用同一套实现。
还没做的都带触发条件记在 [设计.md](docs/design/设计.md) §1.2，不写无条件的 TODO。

**有一条验证从来没发生过：一个真人用一次。**
在那之前所有"好用"都是自证的。要推进它只需要一步——把 [试用包](docs/trial/试用脚本.md) 递给一个人：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\make-trial.ps1   # → dist\trial\
```

递出去时只说一句「打开它，选一个你自己的项目，然后告诉我这个项目能不能跑」，**别提示**。
判定提前写死在 [试用脚本.md](docs/trial/试用脚本.md) §4，记录表填回来改名 `试用记录-日期-谁.md` 放根目录。

## 文档怎么读

- [总稿.md](docs/design/总稿.md) —— **从这里开始**。把「为什么做它、它现在是什么、每个决定凭什么」
  收成**一份**能从头读到尾的东西；四条线、证据、错账、边界都在里面。
- [设计.md](docs/design/设计.md) —— 决策书。每条"决定"都写清背景、代价与（该有的）被否方案。
- [数据层设计.md](docs/design/数据层设计.md) —— 实体与关系的唯一真源。
- [复审记录.md](docs/process/复审记录.md) —— 十遍全量复审，每遍换一个视角，以及每遍抓到了什么。
- [tools/motives.json](tools/motives.json) —— 动机清单：用户当初要什么、落在设计哪一处。
  **由 `gate.mjs` 检查**，指不到落点就报错。
- [使用说明.md](使用说明.md) —— 给使用者看的（打包进发行版）。
- [docs/archive/V0-旧合稿.md](docs/archive/V0-旧合稿.md) —— **历史过程稿**（早于《总稿》的那一版合稿，
  2026-10-16 收纳进 `史料/`，头上加了一版说明）。**只作档案，不作为依据**；
  有几条设计要求仅存于此（例如过滤系统的两个出口），引用时要指明"设计要求、未实现"。
