## 二、设计（现行 / 史料分开）

- **现行**：[`docs/design/设计.md`](design/设计.md)（判据与架构）、[`docs/design/数据层设计.md`](design/数据层设计.md)（表与事务）。
- **史料**：[`docs/design/总稿.md`](design/总稿.md)——0.1/0.2 时期的总稿，**已被设计.md 取代**，只作追溯。

## 三、过程（按时间读，不按顺序读）

- `docs/process/要点-<日期>.md`：一行一条的当日要点（干活途中记）。
- `docs/process/工作汇报-<日期>.md`：交付级别的小结（含每轮证据、未完成、下一步）。
- `docs/process/交接-<日期>-新会话.md`：会话到顶时写给下一个会话的一页纸。
- 专题：`删命令候选普查`、`减法重构进度`、`接缝契约审计`、`其他会话-设计与决策点`、`事故账本`。
- **史料**：[`docs/process/复审记录.md`](process/复审记录.md)（大段复审流水，不作现行判据）。

## 四、资料与史料

- [`docs/knowledge/`](knowledge/)：知识条目（claim/source/level/check 四字段），由 `jingwei knowledge` 维护。
- [`docs/research/`](research/)：外部一手来源与观点地图（四类可信度：原话 / 转写 / 二手 / 查不了）。
- [`docs/archive/`](archive/)：**全是史料**（旧合稿、真输入、复盘）。要引用先看日期，别当现行。
- [`docs/trial/`](trial/)：试用期材料，**已暂停**（人明确说不需要搞试用）。
- [`docs/reference/`](reference/)：债表、工作方法、工具链便携边界、失效模式清单。

## 五、怎么维护这份索引

- 新文档落进来 → 在第一节或第三节加一行，写清"回答什么问题"。
- 一份文档被取代 → 移到史料区并加横幅（**不要删**：原文是追溯用的）。
- 判据变了 → 先改 `docs/decisions/`，再改本索引指向，别在史料里改结论。
