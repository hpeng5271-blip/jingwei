# D-20261019-02 · 模块级调用怎么进图谱

- 决策者：`deepseek-v4-pro`（2026-10-19，只读）
- 执行者：`deepseek-flash`
- 触发：债表 0.23 实测出"Python 顶层调用一条都不收"；属跨模块（模型矩阵 + 解析 + 角色）
- 状态：**设计已定，待实现**

## 事实（先说清）

`x = f()` 在模块级 → **0 条调用**；同样的 `return f()` 在函数里 → 正常收。
根因：`calls` 边是 Symbol→Symbol，顶层没有调用者符号，`scope.last()` 为空即跳过。

## 决策

**只收两类，其余不收**：

1. `if __name__ == "__main__":` 块内的调用 → 调用者是**文件本身**（File → Symbol）；
   来源是事实：脚本被**执行**时顶层语句确实会跑。
2. 装饰器注册（`@app.route` / `@click.command`）→ **另起边 kind**（File → 函数，如 `registers`），
   **不混进 `calls`**。

**不收**：裸 import 期副作用调用（`logging.basicConfig()`）——降为 `depends_on` 或明记"未收"。

## 为什么不是"全收"

全收会让每个库模块的顶层多出 1–2 条 out 边，**入口判定被污染**（roles 的出度是入口判据）。

## 副作用（roles）

| 方向 | 规则 |
|---|---|
| 出度 | 只有 `__main__` 块内的调用计入"入口候选出度"——脚本文件才出边，入口判定变准 |
| 入度 | 被顶层调用的符号照常 +1（它确实被文件用了） |
| 装饰器 | 走独立 kind，**不计入 calls 的入/出度**，避免污染 |

## 实现落点（下一轮做）

1. `crates/model/src/lib.rs::allows`：`Calls`/`References` 增加 `(File, Symbol)` 一格（**只为 __main__**）；
2. `crates/engine/src/graph/index.rs`：建 `calls` 边时按 `caller` 前缀（`file:`）选 `NodeKind::File`；
3. `parse_python.rs::collect_calls`：加"模块调用者"参数；遇到 `if_statement` 且条件含
   `__name__` 与 `__main__` 时，进 body 时把调用者设为 `file:{rel}`；
4. 测试（红先）：
   - `__main__` 块内 `x = f()` → 恰好 1 条 `File→Symbol` calls 边；
   - 顶层（非 `__main__`）`x = f()` → **0 条**（明确的不收）；
5. `roles`：确认 File→Symbol 不进符号出度；入口候选变准要有实测对比（flask 前后）。

## 验收

- 上面两条测试一红一绿；
- flask：`positions` bad 仍为 0；`roles` 入口候选数变化要有解释；
- 全量门禁绿。

## 最可能翻车点

`calls` 边的**解析期**（resolve）默认"两端都是符号"，File→Symbol 可能在那里被当成符号 id 去查；
必须先确认 resolve 对非 `symbol:` 前缀的处理，再动解析层。
