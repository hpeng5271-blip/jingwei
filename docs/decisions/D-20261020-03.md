# D-20261020-03 · 增量扫描：RDCW + 持久 journal 的实施计划

- 决策者：`deepseek-v4-pro`（学习 #4 的设计）
- 执行者：`deepseek-flash`
- 触发：债 0.13（冷缓存 98.7s）在应用层无解，pro 给出不提权出路
- 状态：**两步都已实现**（`jingwei watch` + `discover --journal`）；Node 版 `scan-changed` 保留作跨平台兜底

## 目标

第二次及以后的 `discover` **只碰变过的目录**；拿不到"变更事实"时**明说查不了**，退回全量。

## 三步（每步都有可判定的验收）

### 1. journal 写者（最长的一块）

- 新命令 `jingwei watch <root> [--root ...]`：进程常驻，用 `ReadDirectoryChangesW`
  （`FILE_LIST_DIRECTORY` + `FILE_FLAG_BACKUP_SEMANTICS`，`bWatchSubtree=TRUE`）收事件；
- 每个事件追加一行到 `%LOCALAPPDATA%\jingwei\watch.jsonl`：`{ts, action, path}`；
- **验收**：起 watch → 在根下新建/改名/删除文件 → journal 出现对应路径；Ctrl-C 后文件可读。

### 2. journal 读者

- `discover` 启动时若 `--use-journal` 且 journal 非空：取其中路径的**父目录集合**，只扫这些目录（depth 1）；
- journal 不存在 / 为空 / 上次 watch 早于 journal 窗 → **退回全量**，并打印原因；
- **验收**：全量扫一次（落缓存）→ 起 watch 改一个项目 → `discover --use-journal` 只报那个项目，
  且输出里写明"增量：只扫 N 个目录"。

### 3. 三态口径（不许压扁）

| 情况 | 怎么说 |
|---|---|
| watch 在跑，journal 新 | 增量：只扫变更目录（N 个） |
| watch 没在跑 | **增量查不了**（没有变更记录）→ 退回全量 |
| journal 坏 / 读不了 | 同上，且把坏文件挪走（留证据） |

## 边界

- 不提权（不碰 USN/MFT）；
- 深目录改动**不会**改祖先 mtime——"mtime 没变=子树没变"是伪判据，禁用；
- 首次仍要全量 walk（这是基线，不是缺陷）。

## 最可能翻车点

`ReadDirectoryChangesW` 的**缓冲区溢出**（`ERROR_NOTIFY_ENUM_DIR`）：变更太多时会丢事件。
处理：收到该错误就**丢弃整份 journal 并退回全量**——比"漏了还当成最新"安全。
