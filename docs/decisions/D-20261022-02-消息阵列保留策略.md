# D-20261022-02 · 消息阵列的保留与"归档"

**背景**：消息阵列（界面）展示"最近发生过什么"，数据来自 `engine::understand::notify`。

**决定**（2026-10-22）：

1. **归档不是永久静音**：归档后同一 key **再次出现**，状态回到 `New`、计数 +1。
   理由：归档是"这条我已经看过了"，不是"以后别告诉我"。
2. **上限 50 条**（引擎侧）：超出时**先丢已归档的**，不够再丢最旧的。
   界面只显示前 8 条并按严重程度排序。
3. **计数会累加**，跨归档保留：同一条发生 3 次就是 ×3（这正是"去重计数"的意义）。
4. 这张表**只在进程内存**里：应用重启就清空。不落盘的理由是它属于"当下的一次会话"，
   要长期追溯应该看 `docs/process/事故账本.md` 与 `债表`。

**代价**：重启后"最近发生过什么"是空的。这是**有意的**——历史归历史，不要拿半个记忆骗人。

**验收**：`crates/engine/tests/notify_gate.rs` 两条——归档后再来变 New、超上限先丢已归档。
