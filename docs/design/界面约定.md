# 界面约定（2026-10-22）

> 这一页不是设计稿，是**已经落进代码的规矩**。加界面之前先对一遍：下面的每条都写着"落在哪个函数"，
> 违反它不需要争论——改之前先想清楚为什么这条不再成立。
>
> 为什么要有这页：这一天新加的角标、计数、消息阵列、结果行，靠的是同一批判断；
> 不写下来，下一个人（或下一个我）会把每一处重新推一遍，还推得不一样。

## 一、有才显示，没有就不占位

- 错误角标 `#tiErr`：没有 error 就 `hidden`。
- 编辑器诊断计数 `#edDiagCount`：没有诊断就收起。
- 消息阵列 `#msgFeed`：没有消息就是空（`::empty` 不占高度）。
- 更新窗 `#updatePanel`：三数字没变就不出现。

**反面**：给"暂无数据"留一块常驻区域。人会把"空着"读成"没问题"。

## 二、点了就跳，不弹窗

- 行号标记、工具栏计数、结果行明细、错误角标、"最近"那一句——**点击一律是跳转**，复用 `gotoDiag` / `dockShow`。
- 只有"需要确认"的动作才出现按钮（应用改动、按清单改名、允许网络）。

**为什么**：弹窗抢焦点，而这里的信息大多"值得看一眼、不值得打断"。

## 三、一行是结论，展开才是明细

- 结果行 `resultLineHtml()`：一行给出"检查 N 处 / 测试 N 处定位"，点「明细」才逐条列。
- 协议条：三数字在前，`reason` 与 `来自 …` 在后。

**判据**：默认状态下**一屏不出现超过三行同类信息**；超出的进明细。

## 四、同一件事只有一个数据源

| 事 | 唯一来源 | 落在 |
|---|---|---|
| 检查 / 测试结果 | `DOCK.diags`（`src` 区分 check/test） | 行号标记、结果行、角标、消息阵列都从它推 |
| 消息生命周期 | `engine::understand::notify` | 界面只调 `msg_ingest` / `msg_mark` |
| 首屏三数字 | `cmd_handover::metrics()` | 界面与 `next`/`doctor` 同源 |
| "刚才" | `tasks.json` 最近一条 | 三处 CLI + 角标 + 设置页同形 |
| 网络允许 | `sandbox_allow` 允许表 | CLI `net` 与界面按钮都调它 |

**规矩**：新做一块信息之前，先问"这个数据已经有主了吗"；有就复用，没有才新增采集。

## 五、数字必须追得到命令

- 协议条的「来自 `<ref>`」= `evidence[0]`，点一下复制命令，能自己复跑。
- 三态 `unknown` 必须配"缺什么 / 为什么 / 怎么补"，不许只写"查不了"。

## 六、别抢注意力

- 错误窗只在**有 error** 时自己出现；静音窗口由引擎的 `silence_secs` 决定（界面不自算）。
- 更新窗弹一次就记住（`localStorage` 快照）；同一次变化不重复弹。
- 消息重复出现只加计数（×N），不刷屏。

## 七、空着等于隐瞒

- 测试失败但**定位不到行**：结果行写"测试失败（没定位到行）"，不许整行消失。
- 读不到允许表：「读不到允许表（…）——这不等于"什么都没允许"」。
- 图片/数据还没到时不要把占位图当结论。

## 八、怎么验证这些约定

这些不是口号，都有断言守着（`node tools/uitest.mjs`）：

- 角标/计数/消息阵列"有才显示"：`错误角标：有 error 才亮…`、`编辑器：工具栏上有诊断计数`、`消息阵列：归档后行消失`
- 点了就跳：`编辑器：点标记跳到那一行`、`点环境开设置、点检查开问题栏`
- 一行是结论：`结果行默认不展开、点一下出明细`
- 同一数据源：`最近结果：检查与测试分开计数`（都来自 `DOCK.diags`）
- 别抢注意力：`错误窗：静音期内不自己跳出来`、`更新窗：同一次变化不重复弹`
- 空着等于隐瞒：`测试失败但没定位也要说出来`

**加新约定时，同步加一条断言**——否则这页迟早变成愿望清单。
