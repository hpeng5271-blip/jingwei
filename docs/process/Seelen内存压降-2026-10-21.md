# Seelen UI 内存压降（2026-10-21，不关闭 Seelen）

## 结论

| 项 | 改前 | 改后 | 变化 |
|---|---|---|---|
| `seelen-ui.exe` 主进程 | 148 MB | 153 MB | 持平 |
| 它的 WebView2 子进程 | **12 个 / 896 MB** | **7 个 / 593 MB** | **−303 MB** |
| **合计** | **≈ 1,044 MB** | **≈ 746 MB** | **−298 MB（−29%）** |

功能实测：重启后顶栏照常（时间 / 输入法 / 系统托盘都在，见截图核对），没有报错。

## 怎么做的（一条环境变量，可逆）

```powershell
# 只影响"新创建"的 WebView2 实例；设置后重启 Seelen 生效
[Environment]::SetEnvironmentVariable(
  'WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS',
  '--renderer-process-limit=2 --js-flags=--max-old-space-size=96 --disable-features=msWebOOUI,msPdfOOUI',
  'User')

# 让 Seelen 重启（它装了服务，杀了会自动起）
Get-Process seelen-ui | Stop-Process -Force
```

**撤掉**：把那个环境变量删掉（`[Environment]::SetEnvironmentVariable('WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS',$null,'User')`）再重启 Seelen。

试过更激进的组合（`--renderer-process-limit=1 --disable-gpu-compositing --disable-dev-shm-usage --max-old-space-size=64`）：
**进程 6 个但合计 680 MB，比现在更差** → 已退回现在这组。

## 为什么"内存高"不全是 bug（有出处）

- 作者在 [issue #1081](https://github.com/eythaann/Seelen-UI/issues/1081) 里两次说过：
  1. *"this scales to Tauri and Webview2, is not a issue on the code of the application"*（2025-07-18）
  2. *"memory leak fixed since v2.4.7"*（2025-11-23）
- 我们现在是 **v2.8.9**，泄漏已修；剩下的 ~750 MB 是**结构性的**：**每个小组件 = 一个 WebView2 实例**。

## 版本评估（要不要换版本/重装）

| 版本 | 判断 |
|---|---|
| **v2.8.9（当前）** | ✅ 最新稳定版，泄漏已修；**不建议降级** |
| 2.4.x 及更早 | ❌ 有内存泄漏（作者原话），更差 |
| Nightly | ⚠️ 功能更超前，但同样每个组件一个 WebView2，**内存不会更低**；且更易碎 |

结论：**不重装、不降级**。降低内存的杠杆只有两个：① WebView2 参数（已做，−298 MB）② **减少小组件数量**（每个约 70 MB）。

## 还能再降的地方（需要点界面）

顶栏/底栏上不用的组件，**右键那个图标 → 「移除模块」**，或右键空白处 → 模块 → 取消勾选。
按你之前说的"只要 系统 / 时间 / 输入法"，把 网络速率、内存、磁盘、蓝牙、媒体、通知、快速设置、工作区 全去掉，
预计还能再省 **200–280 MB**（3–4 个 WebView2）。

> 我为什么没代点：这套 UI 的右键菜单会在指针移动时收起，我上次盲点误开过一个 Google 登录页，所以这一步交给你（20 秒）。
