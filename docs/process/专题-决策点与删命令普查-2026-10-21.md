# 一、删命令候选普查（原文）

# 删命令候选普查（2026-10-21）

## 我先前的假设是错的

计划里写"真删 `snap` / `clean` / `env`"，理由是"看着没人用"。**grep 一跑就不成立**：

| 命令 | 提到它的文件数 | 说明 |
|---|---|---|
| `env` | **130** | 环境检测是核心概念，不可能删 |
| `clean` | **33** | 清理是"能删什么"的一整条线，文档/规则里到处都是 |
| `snapshot` | **26** | 快照概念在多处复用（扫描缓存、环境快照…） |
| `snap` | **8** | 与 `snapshot` 语义重叠，删它要连概念一起理 |

## 结论（修正计划）

1. **"按感觉挑三个删"是错的**——`env` 根本不是候选，`clean` 是一条线不是一个命令。
2. 真正该删的判据应该是：**只有它自己、没有别的命令/文档依赖的概念**。按这个口径，候选要重新挑。
3. 更稳的路：**先量使用，再删**。但仓库现在**没有命令调用日志**（`limits.mjs` 统计的是 pro 咨询，`rounds/decisions` 都是 0）。
   → 所以第一步不是删，是**加一行调用记录**（`~/.jingwei/usage.jsonl`：时间 + 命令名 + 退出码），攒够窗口再按真实调用数删。

## 下一步（替换原计划）

| 原计划 | 改成 |
|---|---|
| 删 `snap` / `clean` / `env` | **先加 usage 记录**（`~/.jingwei/usage.jsonl`），攒够窗口再按真实调用数删 |
| —— | 同时：把 `env` 从"候选"里永久划掉（130 处依赖，是核心不是尾巴） |

**判据**（2026-10-21 晚由 pro 复核后改，落 `docs/decisions/D-20261021-06-命令调用记录.md`）：
**28 天**窗口（原写"一周"——一周样本太薄，删命令是低频决策）、调用次数为 0、`grep` 引用确认无测试/文档依赖、
人签字，**四者缺一不删**；窗口不足 28 天时只许报"样本不足"，不许报候选。

# 其他 DSH 桌面端会话里的设计与决策点（2026-10-21 抽取）

## 一、抽取方法与局限（先写，免得把"我没抽到"当成"当时没定"）

**存储形状**（踩过才知道）：`~/.dsh/sessions/<工作区>/<会话id>/session.v4.jsonl.zstd`
是**多帧 zstd 拼接**（每帧一段 JSONL）。Node 的 `zstdDecompressSync` 只解第一帧，
流式解码器遇到第二帧直接报 `Unknown frame descriptor`——所以按 zstd 魔数切帧、逐帧解。

**消息形状**（第二处坑）：`user/message` 的正文在 `data.content[]`，
而 `assistant/message` 的正文在 **`data.message.content[]`**。第一版按 `data.content` 取助手消息，
结果**全部为空且不报错**——"抽不到"和"没有"在这一步长得一模一样。

**抽取判据**：人说的话（`text`）全收；助手的结论（`text`）收；助手的思考（`reasoning`）
只在明确谈决策/判据/口径时收。再按主题归并，**试探性的标「试探，未定」**，不许把思考当决定。

**已知局限**：

1. 只覆盖本机存着的 15 个会话；更早的会话已被清理（`~/.dsh/_removed-20261019`、`_cleanup-backup-2026-10-19`）。
2. 按关键词与长度筛，**没提到关键词的决策会漏**（例如"这个先不做"这种短句）。
3. 子智能体会话里的 `user` 消息往往是主会话塞进去的任务书：**要求 ≠ 结论**，本文分开标。
4. 时间戳来自会话 `createdAt`，不是每条消息的时间。
