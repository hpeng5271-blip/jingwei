### 这一段的三个真教训

1. **CRLF**：改 `cmd_doctor.rs` 的补丁脚本连改四版才落上——前三次锚点按 LF 写，全不匹配。

### 这一段的主线

不是加功能，而是**把"会骗人的地方"逐个堵掉**：

- 数字没有出处 → 标 `来自 <命令>`；
- 文件有几处问题要低头找 → 工具栏计数；
- 允许表过期了还写着"还剩 23 小时" → 定时对账；
- 内存态被当成持久记录 → 明写"重启会清空"；
- 文本版比 JSON 少信息 → 补齐三数字。

### 三个"自己踩"的坑（都已记进失效模式清单的思路里）

1. **CRLF**：`cmd_doctor.rs` 的补丁连改四版才落上（锚点按 LF 写）。
2. **mtime**：`Copy-Item` 恢复文件带走 mtime → cargo 不重编 → "恢复了还红"。
3. **反引号**：用模板字符串写含反引号的 Markdown → `SyntaxError`；改单引号数组 join。

结论：**工具链的坑比业务逻辑的坑多**，所以每轮都留证据（命令 + 输出），否则第二天连自己都说不清。
