## 3. 该怎么改（按"能不能立刻做"排序）

### P0-1 · L9：**删掉抑制机制**，而不是实现它

- 事实：`Level::Silent` 全仓 0 处 → 这个机制**要么从未实现、要么已被移除**
- 两个选择：
  - 实现它（新功能，要设计"时间出口/位置出口"）
  - **删掉它**（把 `使用说明.md` 里那段"从来没实现"的描述一起删）
- 我选**删**：现在没有任何一条结论被压下，所以"两个出口"没有对象。**不要为不存在的功能写文档。**

### P0-2 · L10：把 UI 变量族收成一个

- 现状：`ui/style.css` 里 `--t-*` 23 处、`--dur*` 0 处；历史记录（P9）说曾经反着来过
- 改法：只保留 `--t-*` 一族，删掉任何 `--dur*` 残留；加一条**测试**：`ui/**.css|js` 里出现 `--dur` 即红
- 判据：改一个动画时长，`grep --dur` 为 0 且页面三处同时变

### P1-1 · L2：补一条"插行不改身份"的测试

- 用例：同一段源码，在函数头插一行空行 → 该符号 `id` 必须不变
- 成本：一条集成测试；收益：把"增量不炸"的前提钉住

### P1-2 · L7：补一条"冲突两边都在"的测试

- 用例：契约写 `python 3.11`、PATH 只有 `3.9` → 输出必须同时含两个值 + 判"矛盾"
- 现状：`deps_check` 有"判不了"通道，但**没有冲突用例**

### P2-1 · L11：先把"同一件事"定义出来，再谈跨项目

- 建议的最小定义：`(规则 id, 三态结论, 证据行号)` 三元组在两个项目里**格式相同**即可比
- 不做：全局库、跨项目索引（那要先有 G3/L11 的判据）

### 不做（明确写下来，防"顺手加"）

| 不做 | 理由 |
|---|---|
| 实现 `Level::Silent` 的两出口 | 现在没有"被压下的结论"，做了也没有对象 |
| 全局知识库 | L11 判据没定，先做就是猜 |
| LSP | 触发条件未到（跨文件边准确率还不是第一抱怨） |
| 沙箱 / MCP | 单用户本机场景，价值不在 |
| 场景化"顺手加一个操作" | 操作层准入门槛：**它产生什么事实？进哪个认知回路？** 答不出就不做 |
