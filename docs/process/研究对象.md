## 二、它们抓出来的真缺陷（全部是"造夹具抓不到"的）

| # | 缺陷 | 由哪个对象抓出 | 修法 | 门禁/测试 |
|---|---|---|---|---|

## 三、还欠什么（研究对象这条线）

1. **更复杂的复合结构**：现在最复杂的是 vite（pnpm workspace）。**还没吃**：
   Rust + 前端同仓（如 `tauri`）、Java 多模块（Maven multi-module）、Python monorepo；
2. **大规模性能**：最大对象 2,868 文件；**没有**在 1 万+ 文件的项目上量过 `index` 耗时与内存；
3. **角色判定的人工抽检**：只在 3 个项目上看过点名，**没有**逐文件核对"入口/底层"判得对不对。
   做法应该像 `标注记录.md` 那样：抽 N 个文件 → 人工判 → 对机器结论，**0 假 0 漏才算过**。

## 五、这轮实测撞出来的两个真结论

### 5.1 Node / Java：**判得出、画不出**——这是边界，不是 bug

`index` 目前只解析 `.rs` / `.py`。vite（940 个 .js、586 个 .ts、26 个 .vue）与
petclinic（50 个 .java）的结论是**诚实的三态**：

> `扫到 0 个文件——这个目录里没有我们能解析的源码（目前只支持 .rs / .py）`
> `它有：940 个 .js、586 个 .ts…` → **不是你没有源码，是我们还没支持这门语言。**

**能做的部分照做**：`guide` / `doctor` 仍然工作（读 `package.json` / `pom.xml`，
给出能不能跑、缺什么）。**所以要写清**：这两类项目我们**给结论、不给图谱**。

### 5.2 Python 的相对 import 没解析 → **角色判定不可信**（真缺口，量化了）

flask 里 **102 处 `from .x import`**（相对导入），而图谱里 `src/flask/config.py`
（被 `app.py` 导入）是 **0 入 0 出 → 被判成「还没连上」**。
结果：83 个文件里 **18 个 isolated**，跨文件调用只有 202 条——**明显偏低**。

**影响**：对 Python，`graph roles` 的"入口/公共底层/还没连上"**现在只能当线索，不能当结论**。
**修法（下一步）**：解析相对导入（`from .x` / `from ..pkg.x`）→ 解析成包内模块路径 →
补 `calls` 边；判据：flask 的 isolated 从 18 降下来、`config.py` 至少 1 条入边。
