## 二、它们抓出来的真缺陷（全部是"造夹具抓不到"的）

| # | 缺陷 | 由哪个对象抓出 | 修法 | 门禁/测试 |
|---|---|---|---|---|
| 1 | **`Makefile` 被当 C/C++ 语言标记** → 所有带 `make test` 的 Python 项目被判成"C / C++ + Python 混合" | requests、flask | `Makefile`/`meson` 降为最后兜底，`CMakeLists.txt` 仍是强标记 | `makefile不是语言标记`（三形状）+ 负向 |
| 2 | `guide` **不读 `package.json`** → 真 Vite 被判"还查不出来，补契约" | vite | 共用 `web::run_script`；Node 无契约有命令 → 能跑 | 窗口门禁 + 真项目复跑 |
| 3 | 真 npm 包 **`pnpm` 被判"你缺契约"**（它是库） | `@deepseek-ai` 树里的 `pnpm` | `web::is_library`：无启动脚本 **且** 有 `bin`/`main`/`exports` | `node的库与能起的东西分得开` |
| 4 | **Java 项目的装依赖提示是死路**（`jingwei env install` 在 Maven 项目上走不通） | petclinic | `Lang::install_hint()` 按生态给原生命令 | `装依赖的提示要按语言给` |
| 5 | Rust **bin crate 被要契约**（`cargo run` 本来就知道） | 本仓库 `crates/cli`（真实 Rust 应用） | `rustbins::run_hint`，且**库身份优先** | `单个bin才给cargo_run` |
| 6 | `pyproject.toml` 的依赖**一直没被读**（flask 一个依赖都不报） | flask | `pyproject_deps_spec` + 去掉早退 | `pyproject里的依赖要读出来` 等 2 条 |
| 7 | Python 的 `test_*.py` **参与角色判定** | flask | `is_test_file` 补 Python 那半 | `python的测试文件不参加角色判断` |
| 8 | Python 符号节点**路径丢失**（角色全判成"还没连上"） | flask（CLI 对拍时） | `node_paths` 三种形状都认 | `python符号节点的路径要从id取` |

**教训（写进 `SOP.md` S29）**：这些漏洞**不会在自造夹具里出现**——夹具是按我的理解写的，
我漏掉的，夹具也漏。**先修量具，再谈结论。**

## 三、还欠什么（研究对象这条线）

1. **更复杂的复合结构**：现在最复杂的是 vite（pnpm workspace）。**还没吃**：
   Rust + 前端同仓（如 `tauri`）、Java 多模块（Maven multi-module）、Python monorepo；
2. **大规模性能**：最大对象 2,868 文件；**没有**在 1 万+ 文件的项目上量过 `index` 耗时与内存；
3. **角色判定的人工抽检**：只在 3 个项目上看过点名，**没有**逐文件核对"入口/底层"判得对不对。
   做法应该像 `标注记录.md` 那样：抽 N 个文件 → 人工判 → 对机器结论，**0 假 0 漏才算过**。
