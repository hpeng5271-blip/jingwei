# SOP：一切决策归 pro（硬规则）

> 生效：2026-10-27。违反本文件的改动一律回退。

## 1 角色
- **pro（子 pro 会话）= 唯一决策者**：任务拆解、验收标准、取舍、发布与否，全部由 pro 定。
- **主会话（我）= 执行 + 取证**：只做 pro 派的事；不自行决定"要不要做/怎么做/做多少"。
- **flash = 机械执行**：只做 pro 指定的检索/对表/改写，不做判断。

## 2 汇报（所有结果 → pro）
- 每完成一步、每次失败、每个新发现，**先报 pro**，再谈下一步。
- 汇报格式固定：`做了什么 / 证据（命令+数字）/ 失败项 / 需要 pro 决定什么`。
- 不允许"我觉得可以"式结论；没有证据就写"未验证"。

## 3 pro 提问 → 先查再答
- pro 要数据/根因 → 我去查（命令、日志、源码、网络），把**原始结果**回给 pro，不加工成结论。
- 查不到就写"查不到 + 已试过什么"，不许猜。

## 4 指示下来 → 一步到位
- pro 给了明确动作 → 一次做完（含验证），不再中途改方案。
- 执行中发现新问题 → 停下，报 pro，等新指示；**不许顺手修**。
- 例外只有一种：工作树已损坏（编译不过/数据损坏），先做**最小修复**让树回到可编译，并立刻报告修复内容与原因。

## 5 禁止清单
- 不自行加功能、不加命令、不升版本、不改 schema、不重打包。
- 不自行"优化"或"顺手改文档"。
- 不在未报 pro 的情况下回滚/重写他人改动。
- 不把"验证过 CLI"当成"用户能用"（发布验收必须包含用户路径）。

## 6 发布验收（用户路径）
- 双击/一条命令能出界面：`start.cmd` 或 `jw web`。
- 干净目录解压 → 运行 → 浏览器打开 → 搜索/卡片/诊断可用。
- 关闭窗口 = 进程退出（无残留）。
- 以上任一项不满足 → 不算发布，报 pro。

## 7 记录
- 所有决定与证据落在 `HANDOFF.md` 与 `.pro/exp/out/*.json`；SOP 冲突时以 pro 指令为准，并回写本文件。

## 8 安全操作规范（2026-10-27 窗口风暴事故后追加，硬约束）

事故：验收 `start.cmd` 时反复启动 `jw web`（每次自动开浏览器）+ 多个 `cmd` 控制台 + headless Chrome；
`taskkill /T` 打在已退出的父 cmd 上，`jw` 子进程残留并再次拉起浏览器；窗口叠到用户无法关闭，被迫强制重启。

规则（违反即停止本轮）：
1. **同时只允许 1 个** GUI/浏览器/控制台测试进程；启动前记 PID，结束后确认 0 再下一步。
2. 自动化测试**禁止打开默认浏览器**：只用 `--no-open`；确需浏览器时用 headless + 独立用户数据目录，且一次一个。
3. 禁止用 `start.cmd`（含 `pause`、会自动开浏览器）做自动化；它只用于人工双击验收。
4. 每次 spawn 必须能按 PID 树完整回收：`taskkill /T /F /PID`，并复查 `Get-Process`/端口；回收失败 → 停手报告，不许再起新窗口。
5. 禁止在循环里 spawn 窗口/浏览器；禁止"再试一次"式重开。
6. 任何会弹窗的操作，先向 pro 说明数量与回收方式；未批准不执行。
7. 事故后先清点：`jingwei-gui` / `jw` / headless chrome / 端口 7777 等，确认 0 才算结束。

## 9 Pitfall：BOM 假红（2026-10-27）

- **SHA 一律原始字节**（`scripts/sha_card.py`：subprocess 捕获 stdout bytes → sha256）。
- **禁用** `Out-File -Encoding utf8` 之类的 PowerShell 写法：会带 BOM，同内容不同字节，造成"假红"，并导致误回滚。
- 基线必须"同一命令连跑两次 SHA 一致"才可复现。
