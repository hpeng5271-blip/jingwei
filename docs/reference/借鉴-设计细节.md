## 1. salsa / rust-analyzer：用 revision 判断"能不能复用"，而不是重哈希

**问题**：二次启动/增量时，怎么不重算、不逐字节比对，就知道某文件的解析结果可复用。

**设计**

1. 每个输入是 tracked struct，字段一变全局 revision +1（单调整数，非哈希）；
2. 查询结果 memoize，并记下"这次读过的输入字段"（依赖集）；
3. 回答时只比依赖字段的 revision，没变→直接返回缓存，O(1) 不碰内容；
4. durability：几乎不变的输入（解析器版本/配置）标低变更频度，比较时跳过；
5. 变更只沿依赖图向下传播，无关文件完全不检查。

**我们的落法（可直接做）**

- `store::file_results` 现在只有 `result_sha`（内容哈希逐字节比）；
- 加一列 `file_rev INTEGER`（单调递增，每次写该文件 +1）+ 保留 `EXTRACTOR_VERSION`；
- 二次启动：先比 `(file_rev, extractor_version)`，不变就**跳过、不重哈希内容**；
- rev 变才重解析 + 重算 `result_sha`；哈希只作为"内容真变了"的第二道确认。

**出处**

- https://github.com/salsa-rs/salsa
- https://github.com/rust-lang/rust-analyzer/blob/master/docs/dev/architecture.md

## 2. tree-sitter：增量解析——只重解析改动的区间

**问题**：只改几行也整文件重解析，浪费；也让"内容变但结果没变"的早期截断失去粒度。

**设计**
1. `ts_parser_parse` 接受旧 `Tree` + 一个 `TSInputEdit`（`start_byte`/`old_end_byte`/`new_end_byte`），只重解析受影响区间；
2. 未变子树被复用（节点指针不变），改动祖先从下往上重建；
3. `ts_parser_set_included_ranges` 限定范围，只解析值得解析的 range；
4. 用 **byte 偏移**（不是行号/字符数）定位编辑，避开 CRLF/UTF-16 歧义；
5. 按"节点是否复用"决定重抽符号——复用子树直接沿用符号。

**我们的落法（有前提，别急着写）**
- 落点：`graph/parse.rs` 现在每文件从头 `parse`；改成保留上次 `Tree` + 内容快照，diff 出 `TSInputEdit` 喂回；
- **前提**：`Tree` 只能活在**长驻进程**里（CLI 跑完就退出，拿不到收益）；
- 所以先在 **GUI 的 watch/重索引路径**做，CLI 不动；没有基准证明收益前不合并。

**出处**：https://tree-sitter.github.io/tree-sitter/using-parsers（Incremental parsing / `TSInputEdit`）
