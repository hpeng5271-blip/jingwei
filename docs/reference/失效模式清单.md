# 失效模式清单（从史料里浓缩出来的）

> 2026-10-21 从 `docs/process/复审记录.md`、`docs/process/事故账本.md`、`docs/archive/*` 里提炼。
> **原文归档、经验留在这里**：每条都能对上一个"现在守着它的东西"（测试 / 门禁 / 协议字段）。
> 用法：动手前扫一眼，问"我这次的改动会不会让第 N 条复发"。

| # | 失效模式（现象） | 根因 | 现在由什么守着 |
|---|---|---|---|
| 1 | **部分当全部**：入口 5 个里只验了 1 个，仍说"入口就这几个" | 只报结论、不报覆盖度 | 协议里的 `coverage{read,total,partial}`；缺它测试红 |
| 2 | **查不了被显示成没有**：`positions` 的 ✓0/×0 让没索引的项目"通过" | 三态被压成两态 | `state ∈ {yes,no,unknown}` + `partial=true`；GUI 只按 state 分三支 |
| 3 | **两种出口两种说法**：`--json` 打纯文本、stdout 为空 | 每个命令各写各的输出 | `protocol::envelope` 唯一出口；查不了也要 JSON |
| 4 | **同一件事两份真源**：CLI 与外壳各拼一份 JSON，先后漂移 | 没有唯一形状 | `reason` 与 `summary` 同文；GUI 直接吃 CLI 的 JSON（`cli_json`） |
| 5 | **测试/工具污染真实数据**：门禁与集成测试往真实 `usage.jsonl` 里写 | "非人调用"没被隔离 | 测试夹子与 `knowledge-gate` 都指到临时文件 |
| 6 | **门禁只证自洽**：全绿 ≠ 可信（曾恒真、曾随机红、曾对已删元素只报 exists:false） | 门禁自己会坏，且没人验它 | 判据必须能"先红"；**门禁绿只当必要条件** |
| 7 | **凭感觉删东西**：删 `snap/clean/env`（`env` 实际 130 处依赖） | 没有使用数据就动手 | 先量再删：计数 + grep 无依赖 + 人签字，缺一不删 |
| 8 | **不可逆却说成功**：改名改到一半、只写了一半文件 | 写操作没有事务 | 编辑/改名：预演 → 确认 → 原子写 → 回读；判不准整次拒绝 |
| 9 | **编码/BOM 让"修好了"不生效**：`trim_start()` 不认 BOM | 文本边界没处理 | 读文件一律先剥 BOM；测试用带 BOM 的样本 |
| 10 | **增量 ≠ 全量**：增量索引丢掉跨文件调用边 | 符号表来源不同 | `incremental_equivalence`：增量结果 == 干净库全量 |
| 11 | **"优化"引入回归**：带提示二次解析（2167→2148 符号） | 讲不清的数字变化被当成收益 | 量出回归就**整块回滚**；不接受自己讲不清的变化 |
| 12 | **自测死在环境上**：`check-docs` 的自测 `mkdtemp` EPERM，门禁整条没跑起来 | 测试依赖了环境 | 自测只用内存字符串，不碰磁盘 |
| 13 | **共享文件让并行测试互相打架**：任务日志按"进程 id"落盘，并行测试共用一个文件，读到别人留下的 `running` | 隔离粒度选错（该按测试、不该按进程） | 每个测试一份临时文件；断言失败信息里带上读到的那条 |
| 14 | **假功能**：错误窗写好了，但数据源里根本没存 `findings`，面板永远不会出现 | 只测了纯函数，没查"数据到得了吗" | 接线后必须有一条**端到端**断言（数据 → DOM）；纯函数测试不算数 |
| 15 | **旧工具测旧形状**：`smoke-pack` 还在找 zip 与包内演示项目，包早改成了目录 | 包格式变了，验证脚本没跟着变 | 包冒烟改为**自己铺演示项目**：不依赖包内附带什么 |
| 16 | **异步改了签名却漏改调用**：`await` 加进非 `async` 函数，`node --check` 立刻红；断言没 `await` 时"看起来绿" | JS 没有类型检查兜底 | 改 `async` 必须同一次改调用处；断言里 `await` 一遍；`node --check` 进提交前流程 |
| 17 | **两个实现同一条判据**：静音公式差点在 JS 里再抄一份 | 界面拿不到引擎的判定，图省事抄公式 | 判据只在引擎一处；界面通过 `notify_gate` 问，不许自算 |

## 用法（比"记住"更可靠）

- 改动前：这次会碰上面哪几条？
- 改动后：哪条测试/字段会因此红？**红不了就是没守住**。
- 新发现的失效模式：**加一条进来**（清单条数 = 事故总数），并顺手补一个能红的东西。
