## 一、一句话

这套材料教的是"**先问为什么，再学怎么做**"：架构是取舍，知识会衰减，经典当历史书读。
它给的是一条补课顺序——先立 why、再看取舍、最后要能验——不是书单，也不是产品用法。
材料里没有"读完就会"的承诺。

## 二、按顺序学什么

1. **先立"为什么"（know-why > know-how）**——排第一，因为它决定后面每份材料的读法：不先问"它解决什么问题"，读什么都是抄结论。读 `docs/research/原子能-转写要点.md` §一 1–2 条 + 转写原文 `docs/research/transcripts/BV1GAyZYAEwA.txt`（#20）。**20–30 分钟**。
2. **架构 = 取舍**——第二，因为取舍是全部主张的主干：选型、交接、立规矩都从它长出来。读 `原子能-转写要点.md` §二 第 1–5 行（取舍 / 被绑定 / 项目关心什么 / 扩展边界 / 简单优先）+ `原子能-观点地图.md` §一 A 组；原视频 #1 `BV1S34y1F7pN`（转写原文不在库，见 §四）。**45–60 分钟**。
3. **选型：越小越省事**——第三，因为这是取舍的可执行版，能直接对照经纬的依赖闸，而不是停在态度上。读 `原子能-转写要点.md` §二 后六行（技术栈 / 过度开发 / 规则进 CI / 别造轮子）+ `docs/research/一手来源.md` §4 的 Choose Boring Technology；原视频 #2 `BV1NQ4y177AN`（原文不在库）。**30–45 分钟**。
4. **知识衰减与交接**——第四，因为它的落点是"决策记录 + 知识库贴代码"，正好是经纬的理解层；排在选型之后，是因为得先有判断才有得记。读 `原子能-转写要点.md` §三 2–4 条 + `docs/decisions/README.md`（看"为什么不是别的"这一节该长什么样）；原视频 TRAE `BV1gvpg6zEtT`（原文不在库）。**45–60 分钟**。
5. **拿判据验自己**——第五，因为前四步给的是主张，这一步给"凭什么说主张是真的"；跳过它，前面就只是收集观点。读 `框架.md` §九（9.1 真输入 / 9.2 量具先坏 / 9.3 对照组 / 9.4 上下文是成本），**只读这一节**。**30–45 分钟**。
6. **各域挖一口一手井**——第六，因为"一手"要等有了具体问题再挖，否则是囤书单。读 `docs/research/一手来源.md`，四域**只选一口**：图（stack-graphs / SCIP）／OS（SQLite 原子提交、WAL）／信息论（Shannon 1948 §1–2）／协作（《人月神话》第 2、19 章 + Maker's Schedule）。**60–90 分钟（一口的量）**。
7. **长期背景：把环境换成英文**——最后，因为它是慢变量，不占前置，但决定一手来源读不读得动。读 `原子能-学习来源摘录.md` 里英语那条（#12 `BV1HM4m1Z7QV`，B 段），做法是换界面 + 泡原版论坛。**这是他的个人经验，不是可复现结论**。**每天 20–30 分钟，按月计**。

## 三、怎么验"真的学会了"

1. **讲因果链**：用 3 句话讲清"只有 know-how、没有 know-why → 重写比改容易"，并举一个**自己仓库里**的反例（哪个模块只有"怎么改"、没有"为什么这么设计"）。举不出反例 = 没学会。
2. **读一条真决策**：打开 `docs/decisions/` 任选一条，说出它**否决了哪个方案、为什么**；再指出该记录缺哪一项（例如"最可能翻车点"空着）。说不出被否选项 = 只读了结论。
3. **判债的性子**：在 `docs/reference/债表.md` 开头挑一条欠账，判定它属于"know-why 没记下来"还是"还没做"，并给出判据（哪一行、哪个证据）。判不出就明说"判不了"。
4. **给一次对照**：对"某个设计更好"拿出同一夹具下的**两套数字**（`框架.md` §九 9.3）；拿不出数字就写"这条只能靠人看"，不许用"感觉好多了"结案。
5. **点出两处不可信**：指出材料里至少两处"查不了"（未转写的直播 / ASR 错字 / 产品名不可信），并说明为什么不拿它当判据。
