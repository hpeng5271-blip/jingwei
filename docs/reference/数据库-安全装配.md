# 数据库：装配与安全（我们怎么用、用户怎么信）

> **先说结论**：**本项目不需要用户下载数据库**，也不会在你机器上装服务。
> 我们用的是 **SQLite，静态编进 exe**（`rusqlite` 的 `bundled` 特性）——
> 没有服务进程、没有网络端口、没有口令要管。**这是"便携"这条线的一部分。**
>
> 这份文档回答两件事：① 我们自己的库放在哪、怎么保证它不坏；② **如果将来**真的要接一个
> 外部数据库（用户的项目里需要），"几乎绝对安全"的装配指导长什么样。

## 一、我们自己的库（图谱）

| 项 | 事实 | 自查命令 |
|---|---|---|
| 引擎 | SQLite **静态链接**（`rusqlite = { features = ["bundled"] }`），FTS5/JSON1 自带 | `cargo tree -p jingwei-engine \| Select-String rusqlite` |
| 依赖系统 DLL？ | **不依赖**（不用 `winsqlite3.dll`，不受系统版本影响） | 删掉系统 sqlite 也照跑 |
| 文件位置 | 项目内 `.<数据目录>/graph.db`（`graph_db_path(root)`），**不写注册表、不装服务** | `jingwei index` 后看输出给的路径 |
| 权限 | 只读写这一个文件；不申请管理员 | 普通用户即可 |
| 并发 | 打开时用 SQLite 文件锁；被别的进程占着 → **如实报"库在、读不到"**（退出码 2，不是"你没有"） | `jingwei graph` |

**加固清单（已经做到的打 ✅）**

- ✅ **打包自带**，不下载任何数据库二进制；
- ✅ **不监听端口**（没有 `0.0.0.0:5432` 这类攻击面）；
- ✅ 读路径 `Store::open_readonly` 用于查图谱，写只在索引时发生；
- ✅ 事务：`store::apply_file_update` 四步事务，坏行整批回滚（有测试钉住）；
- ✅ 损坏可发现：库打不开时说原始错误，不说"没有图谱"。

**还欠（记账用）**

- ⬜ 启动时的 `PRAGMA integrity_check` 快速自检（现在只在出错时才暴露）；
- ⬜ 备份/导出按钮（用户想留档时，能一键导出一份 SQLite 或 JSON）；
- ⬜ 库文件被占用的提示里，给出"哪个进程占着"（现在是原始错误字符串）。

## 二、如果用户的项目需要数据库（外部 DB）

我们**不替用户装数据库**，只做"检查 + 给一条可自查的路"。装配指导必须四样齐：

| 必须给的 | 具体到 | 反例（不许出现） |
|---|---|---|
| **官方来源** | 厂商官网/官方下载页的**固定 URL**（写死在代码里，不是搜索结果） | "去官网下载"这种没链接的话 |
| **校验方式** | SHA-256（官方公布的值）+ 我们算一遍对比 | 只说"下载安装" |
| **验证命令 + 预期输出** | 例如 `psql --version` → `psql (PostgreSQL) 16.x`；`redis-cli ping` → `PONG` | "装完试试" |
| **安全边界** | 只听 `127.0.0.1`、不给默认口令、不进 PATH 全局、不装成系统服务（除非用户明确要） | 默认 `sa`/空口令、`0.0.0.0` 监听 |

**已经实现的部分**：工具链那一套（`MissingTool { url, expect }` + `tools/check-need-links.mjs`）
就是按上面这四列做的；**数据库只是"又多一种工具"**，沿用同一套数据结构，不另起一套。

## 三、判据（怎么算"够安全"）

1. **不新增常驻进程**：装完不多个服务；（数据库唯一可能的例外，必须用户显式同意）
2. **不新增网络监听**：默认只听回环，端口写在文档里；
3. **凭据不落明文**：绝不把口令写进契约文件/日志；
4. **卸载干净**：给"怎么删、删哪些目录"的一句话；
5. **每一条都能自查**：命令 + 预期输出，用户能自己验证，不用信我们。

> **边界（写清）**：我们**不审计**用户自己的数据库（账号、权限、备份策略）；
> 我们只保证"**我们碰过的那个文件/那条连接**"是干净的。
