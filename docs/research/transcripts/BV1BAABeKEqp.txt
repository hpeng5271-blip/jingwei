自被世界上最流行的数据库 MySQL 多刀刃发制
比起图定奖得主发明的 Postgres
MySQL 如银销号文章一样漏洞摆除
我说的不是那些万年用不到一次边缘场景
而是人人都会接触到的基础功能
大家都知道
当你常用某一个查询命令的时候
都会先建立一个索引
用来提升查询的效率
比如一个服装的数据表格
你要查找产地是中国的衣服
那肯定要先建立一个产地的索引
那么如果这个表格有不止一个涉及到产地的索引
各位来猜一猜
这个查询聪明的 MySQL 会调用哪个索引
从产地来说
索引二和查询与据更接近
而且体积更小
优先使用它应该合情合理
但实际上在2010年前
MySQL 用的是索引一
在2010年发布5.5版本之后才开始使用
所以原因很简单
原本 MySQL 的设计逻辑是
有多个符合条件的索引时
选最早被创建的
而不是最适合的
如果上面这个例子还不够离谱
接下来这个绝对能让你无语临淹
还是用服装来决定
相信大家都很熟悉
SMLXL 这些马数规格
对吧
储存这些规格信息
我们通常会用到 Enum 这种数据形式
现在问题来了
如果我们需要找到库存里最小和最大的马数
要怎么查询呢
我们都知道比大小可以用得上的语法
有排序的 Order By
和最小最大值的 Min Max
那么这两组查询语句
你觉得哪个能访问正确答案呢
答案揭晓
四个查询语句里有三个的访问正确
只有一个是错的
这道题没答对
绝对不怪你
因为他已经达到了脑筋击转弯的级别了
谜底是
MySQL 在处理 Enum 时有两套规则
在 Order By 语法里
它是根据 Enum 选项定义时的顺序来决定大小的
所以在这个例子里
最先定义的 S 是最小的
最后定义的 XL 是最大的
而在 Min Max 语法里
它会把 Enum 选项当作是制服创来处理
所以在字幕表里
排名靠前的 L 是最小的
最大的自然是 XL
主打的就是一个随意
但是比起下面这个bug
前面那些都只能算小而可
学过数据库入门的都应该熟悉 Trigger
触发系
这个 SQL 基础功能
给数据库提供了事件驱动机制
极大的丰富的应用场景
然而在 MySQL 里面 Trigger 是不能用的
因为它有一个臭名昭著的bug
今年已经20岁的 1147 2号bug
这个bug 出现在一个很基础的 Trigger 应用场景里
比如说你创建了一个 Trigger
用来监听服装表格的改动
如果服装数据直接被修改
那这个 Trigger 会被正常触发
但如果修改是被动发生的
比如它储存的这个买家的 ID 是一个 Foreign Kit
因为买家被删掉了
导致它变成了闹直
这种被动修改在 MySQL 里面就不会触发 Trigger
这就决定了 MySQL 里的 Trigger 是否触发
是完全没有保障的
这个bug 的发现导致 MySQL 使用者
被迫全面抛弃 Trigger 这个基础功能
最讽刺的是
这个 1147 2号bug 被提交的第二天
MySQL 开发团队就留言表示
会在下一个版本修复它
结果20年过去了
除了每年都会有人在评论区
给 11472 唱生日歌
庆祝他的成人礼
MySQL 团队却早已不见踪影
这就是 MySQL 一个缝缝补补的
30年的bug 生产车间
一个纯粹是因为在90年代刚发布的时候
安装起来比较方便
从而抢占了大部分开发者市场的一个残刺品
一个千川百孔的数据库
