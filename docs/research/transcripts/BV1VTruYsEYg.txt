容器技術簡單來說就是通過虛擬化的方式
給程序打造獨立的運行環境
這是一個發展已經很成熟
每個程序人都應該學會的技術
但可能因為出生於系統管理這個小眾領域
大眾對它的接受程度有點三級分化
喜歡的人愛不釋手
討厭的人覺得它就是個增加複雜度的累贅
無感的人覺得我是個血代碼了
又不是什麼運為
這跟我有啥關係
所以為了讓大家能夠更好的接受容器技術
提高它的普及率
今天我們就來聊聊容器
程序人的核心工作就是兩件是
development和operation
把東西開發出來
然後把開發出來的東西用起來
對於前者我們已經摸索出相當多的最佳實踐
比如說通過spring之類的項目管理流程
對開發需求進行系統化的管理
通過git之類的版本控制工具
讓團隊合作能夠高效進行
能夠lighting之類的代碼輔助技術
來維護高質量的輸出等等
但相對於development
我們在operation上的最佳實踐一直少得可憐
把開發出來的東西用起來
不只是簡單的把程序打包放在服務器上
在這個問題上
你想像不出來有些人能有多炒台瓣子
就在幾年前
我親眼目睹了隔壁某個團隊的
補定發布流程
那麼首先是全體成員網上留在公司
等到凌晨3點左右
手動ssh進入每一個服務器
然後手動了ctc/ctv
把寫在發布文檔上的命令
一含一含的貼在每一個terminal上
每執行一含就要確認一次
其中涉及到機密的
比如說數據庫密碼啥的參數
文檔上面沒有寫則是由主長商場手寫
幾十個服務器全部弄完大概要兩個小時左右
我整個人都震驚了
我仿佛置身於一萬年前的山頂洞
這可不是什麼小公司小做法
也不是什麼頑固不化的老行業老企業
而是正兒八經的互聯網大公司
這也說明了相對development人員
operation還是有點野蠻發展的
而容器技術就像是山頂洞人的第一把電鋸
讓operation從原始時代大跨步地進入了工業時代
容器技術最早可以追溯到70年代末的unix
bair實際上是最後發布的一個版本
unix version 7加入了chroot
chroot可以給進程把另一個專屬的更木路
讓這個程序只能在這個更木路的範圍內讀寫文件
所以從一開始
容器技術的使命就是給程序提供一個獨立的隔離的運行環境
然而這方面的技術探索停滯了將近30年
直到2008年 IBM發布了linux containers LXC
簡單來說 LXC就是讓你在linux系統上面跑linux系統
這就比chroot更上一層樓了
LXC不僅是給你一個獨立的文件系統
連設備網絡CPU人底層資源也是獨立的
這種做法被稱為系統操作成虛擬化
相比起完整的虛擬機
它更輕量化
資源需求更少
運行效率也就更高了
但即使是這樣
LXC對於普通程序員來說也還是過於複雜了
因為程序員關心的是他們正在開發的程序
而不是底下的操作系統
所以在2013年
Docker的出現完美的結合了chroot和LXC的優點
它是一個專門為單獨的程序打造的具有完整系統屬性的容器
更重要的是它的設計是對程序員非常友好的
你只需要學會怎麼寫docker file
就能夠自主完成容器的打包
不需要任何sys and min之類的經驗背景
把專業的系統運為問題
轉號為大家都能應對的編程問題
讓容器技術的使用門檻大大降低
但docker並不能解決所有的operational問題
因為它只負責對個體程序進行打包
但在稍微複雜一點的系統裏
你需要處理的可不止一個程序
你還要管理程序間的交流
對資源進行合理分配
總而保障整個系統的穩定運行
在docker發布一年後
Google立馬就發布了Kubernetes
一個用程序化的方式去管理容器集群的平臺
而docker一樣
Kubernetes也是把系統管理以編程的形式呈現出來
而且針對不同複雜度的系統
它還給了你兩種選擇
對於相對固定的系統
你可以直接寫壓模文件
對每個容器每個系統組件
每一塊用到的資源
儲存 算力 裝口 網絡等等
都提前的安排好
而對於更動態的系統
你可以通過Kubernetes SDK
用你最喜歡的變成語言
配合你們的業務邏輯
實時打包 發布容器
動態的調整 集群裏面的各項設置
Kubernetes的設計實在是太合理了
所以在它發布沒幾年後
就以吹哭拉秀的姿態很少了市場
我還記得大概是在17年左右的時候

就是幾個AWS帳號和APACIMISOS集群
整個團隊裏面知道Kubernetes的都沒幾個
所以它們的老大只能勉強給我
開了一個最基礎的集群
平時就是發揚狀態
出啥故障的時候
還得把我叫過去幫忙debug
但就在不到兩年後
整個IT部門基本上已經是全員Kubernetes
Missos基本不見蹤跌
就連它們的AWS帳號上用的服務
也大陸都換成了Kubernetes
這個轉換速度
別說在系統管理領域
就算放在三天一小改
五天一大改的前端領域
也算是非常快了
目前在行業內對於容器技術

那些覺得變麻煩的人

跳過了很多應該做好的本質工作
比如說作為一個程序的作者
你理應準確的告知大家
你這個程序的環境依賴

偷工減料 門後掛拔

他們自然會覺得痛苦不堪
而對於那些認真幹活的人

手動操作的流程
