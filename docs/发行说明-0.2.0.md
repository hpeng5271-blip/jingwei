# 发行说明 · 0.2.0（2026-10-18）

> 包：`dist\jingwei-0.2.0-win-x64.zip`（4.59 MB，49 个条目）
> 验证过：解包后 `jingwei.exe --version` → `jingwei 0.2.0`；对包内演示项目 `hello_rust` 跑 `guide` → **✓ 现在就能跑**。

## 这一版实际变了什么（不是"改了很多"，是这几件）

### 1. 判据：四态在四种语言上都站住了

| 输入 | 结论 | 说明 |
|---|---|---|
| Rust 应用（唯一 bin） | ✓ 能跑 · `cargo run` | 不再要用户补契约 |
| Rust 库 | ? 不适用 | 库没有"跑"这回事 |
| Node 应用（vite） | ✓ 能跑 · `pnpm run dev` | 命令从 `package.json` 读，与 `launch` 同一份 |
| Node 库（pnpm 包） | ? 不适用 | 无启动脚本 + 有 `bin/main/exports` |
| Java（petclinic） | ✗ 跑不起来 | 缺 JDK；装依赖提示改成 `mvn dependency:go-offline` |
| Python（flask / requests） | ✗ 跑不起来 | 依赖没装；`pyproject.toml` 的依赖**现在读得出来** |

### 2. 修掉的真缺陷（都由真项目撞出来）

- **`Makefile` 被当 C/C++ 语言标记** → 所有带 `make test` 的 Python 项目误判成混合项目（requests / flask 全中）；
- **`guide` 不读 `package.json`** → 真 Vite 被判"还查不出来"；
- 真 npm 包 `pnpm` 被判"你缺契约"（它其实是库）；
- Java 项目的装依赖提示是死路；
- Rust bin crate 被要契约；
- `pyproject.toml` 依赖一直没读（flask 一个依赖都不报）；
- `test_*.py` 参与角色判定；Python 符号节点路径丢失（角色全变"还没连上"）；
- requirements.txt / pyproject 带 BOM 时依赖名读成 `\ufeffflask`。

### 3. 界面：画布铺满、信息上四角

- 图谱页**画布铺满内容区**：实测 **96% × 90%**（旧布局 70% × **10%**）；
- 其余页面去掉 1240px 旧限宽；
- 信息按权重分四角：左上状态+按钮 / 左下图例 / 右下最近运行，都半透明、不遮中心；
- 图例没内容时整张卡收起（不留空框）。

### 4. 新增的机器判据

- **文档里列的命令必须真存在**（`checkDocCommands`）：负向验过；
- **画布必须铺满**（≥85% 宽 / ≥78% 高）：负向验过；
- **试用包不许腐烂**（`dist\trial` 与仓库模板逐字节一致）；
- **真源**：文档数字现场重采比对（`tools/facts.json`）。

### 5. 仓库与流程

- 文档分级：指导性留根（`AGENTS` / `框架` / `SOP` / `README` / `介绍` / `使用说明` / `演示脚本`），
  其余进 `docs/{design,process,reference,trial,史料,shots}`；
- **上下文成本砍 60%**：`AGENTS.md` 每轮注入 24.9k → 9.7k 字符（≈11.3k → 4.4k tokens），
  门禁上限随之收紧到 **260 行**；`tools/ctx-cost.mjs` 可随时出成本表；
- 新增 `SOP` 的 S29（真输入撞漏洞）/ S30（设备健康与节省编译）/ S31（上下文双头漏斗）。

## 已知边界（这版**没有**做的）

- **LSP 客户端没开始**（`docs/reference/债表.md` 第 1 条）；
- 大对象只吃到 2,868 文件（vite）；**1 万+ 文件的性能没量**；
- 角色判定**没有逐文件人工抽检**（只有点名核对）；
- 试用暂停（用户口径：先把设计/生产环境把紧）。
