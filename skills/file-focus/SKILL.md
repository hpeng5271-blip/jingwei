# 单文件聚焦：一次问清五件事

## 命令

```powershell
jingwei file src/parse.rs            # 人看
jingwei file src/parse.rs --json     # 机读（协议四件套 + 领域字段）
```

## 它回答什么（四件，第五件是提示）

| 问 | 来自 | 没图谱时 |
|---|---|---|
| 是什么 | 语言（按扩展名）/ 行数 / 字节 / 图里符号数 | 符号数 `null`（**不是 0**） |
| 连着什么 | `DependsOn` 出边数 + 前 5 个 | 同左，`null` |
| 最近动过 | 有 `.git` 用提交时间；否则文件 mtime | 照给，**判据随值一起给** |
| 有没有问题 | **不在 `file` 里算**——明说去跑 `jingwei check` | — |
| 改它影响谁 | 给 `jingwei impact --file` 的提示 | — |

## 三态规矩

- 文件不存在 → `state=no`，exit 2；
- 文件在但**图谱没建** → `state=unknown` 且 **what/why/how 三字段齐全**（说清缺什么、为什么、怎么补）；
- 都有 → `state=yes`。

## 界面上的对应

编辑器顶栏一个「聚焦」按钮：开着时停掉轮询/对账（默认档），按钮写「聚焦中 · 后台 0 项」。
关联文件默认折叠成"信息备选"，**按引用次数排序、最近改动做 tiebreak**，点开才查。

## 别做的

- 不要为了"信息全"去重跑一遍 `check`——那会让单文件查询从 ~40 ms 涨到秒级；
- 不要把"没建图"写成"0 个符号"；
- 不要另起一套文件摘要逻辑，`file` 就是唯一入口。
