# 审改动：只报真问题，不改文件

## 何时用

提交前、跨模块改动后、用户说"看看这段改得对不对"。

## 步骤

1. `git status --porcelain` + `git diff`（已暂存用 `git diff --cached`）。
2. 按**风险**读，不按文件顺序：数据写入/事务 > 解析器 > 公共 API > 文档。
3. 每个问题给：`文件:行` + 触发条件 + 为什么错 + 建议（一句话）。
4. 只报**能复现或能论证**的问题；风格偏好不报。

## 必查清单

- 错误路径：失败时会不会留下半截状态（事务/回滚）。
- 边界：空输入、超大文件、CRLF、UTF-8 BOM、并发。
- 兼容：改了签名/格式，旧数据/旧调用方还能不能用。
- 测试：新分支有没有对应测试；测试是不是只测了 happy path。
- 文档：数字/清单是否还在吹牛（`tools/gate.mjs` 会查一部分）。

## 红线

- **不改文件、不提交**（除非用户明确要求）。
- 不把"我觉得"写成"有问题"；说不出触发条件就不报。
