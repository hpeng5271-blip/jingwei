# 写计划：小步、可验、能反悔

> 改编自 superpowers-zh 的 writing-plans（MIT）：https://github.com/jnMetaCode/superpowers-zh

## 什么时候要写

跨模块 / 不可逆 / 判据变更 / 预计 >30 分钟 / 连续失败后重新开始。

## 计划里必须有（缺一项就是没写）

1. **目标**：一句话，可判定（不许写"优化一下"）。
2. **范围**：改哪些文件、不动哪些（防止顺手重构）。
3. **步骤**：每步 = 一个动作 + 一条验证命令 + 期望输出。
4. **回退**：哪一步出问题就整体退回（git checkout 到哪个提交）。
5. **验收**：跑哪项门禁检查、看哪个数字、谁签字（人/门禁）。

## 粒度

- 一步能在**一次工具调用**里做完；做不完就再拆。
- 每步结束仓库要是**可提交状态**（哪怕只是文档）。
- 同一文件不要在同一步里既改行为又改格式。

## 落盘

- 计划写 `docs/process/计划-<日期>-<主题>.md`，≤1 页。
- 决策级（不可逆/跨模块）另写 `docs/decisions/D-...md`，计划只引用它。
- 计划变了就改计划，**不许只在会话里改**。

## 反模式

先写代码再补计划、计划里没有验证命令、"边做边看"、把待办清单当计划。
