# 三态与不压扁

## 判据

任何一条"有没有 / 行不行 / 装没装"的结论，必须落在**四态**之一：
`是` / `不是` / **`查不了`** / **`不适用`**。
问一句就能分流：**这是"用户的空白"，还是"我们的失败"？**

## 为什么

- 「我们读不到」曾被写成「你没有」：`cmd_graph` 把"库在但读不开"说成"还没建过图谱"，用户去点「索引一次」解决不了他的问题。
- 「不适用」曾被写成「你缺东西」：8 个别人的真 crate（库）全被判成"跑不起来"，让用户"补一个 main"。
- 退出码因此错过两轮：`查不了` 必须 2，`不适用` 必须 **0**。

## 不适用

- **纯内部统计**（例如"这次扫了多少目录"）不需要三态：它没有"查不了"这一格。
- 已经有**确定性事实**（文件存在与否）时，别为了统一而硬套 `unknown`。

## 守卫

`三态各有各的退出码`（crates/cli）· `认库要看_cargo_toml_的_lib_声明`（engine）
