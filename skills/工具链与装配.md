# 工具链与装配

## 判据

三句话：

1. **需求分三层**：项目声明 → 从解析结果推（复用同一次解析，不二次扫）→ 判不出（并说清找过哪些地方）。
2. **链接表是受检数据**：`tools/toolchains.json`，每条必须有 `sha256` / `size` / `host`（在白名单里）/ `verified_at`；缺一条不许用。
3. **三级校验**：静态（门禁每次查）→ 下载时（重定向 ≤1 且仍在白名单、实算哈希、比体积、验签名）→ 装后（**跑一次真实构建**）。

"够不够用"的判据**不是"检测到 rustc"**，而是**能不能跑通一次构建**。

## 为什么

- `rustup` 只装 rustc/cargo，**不装链接器**：`link.exe not found`。只检测版本会给出"能跑"的假结论。
- 未签名（`rustup-init` 就是）曾被判成"校验失败"→ 会把官方文件删掉。**未签名是事实，不是失败**（是 note，不是 problem）。

## 不适用

- 用户已经有完整工具链、且项目能构建时，**不要跑冒烟**（白花时间）；
- MSVC Build Tools 这类**只能安装**的件：我们只引导，**不代跑安装器**。

## 守卫

`工具链清单`（gate.mjs 的 checkToolchains）· `fetch-toolchain.mjs --selftest` · `编不过时是失败_不是缺件`
