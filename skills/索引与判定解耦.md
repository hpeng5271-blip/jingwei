# 索引与判定解耦

## 判据

采集阶段**只记事实**（路径、mtime、有哪些标记文件、被哪条规则跳过）；
"这是不是项目 / 属于哪一层"是**查询**，不是扫描时烧进去的状态。

三条可验：① 同一个根第二次启动**不再重读每个目录的事实**（遍历本身还在——见下）；
② 改判定规则**不用重扫**；③ 一次误判**能用表复现**。

**诚实边界**：只靠 mtime 做不到"跳过整棵子树"——在深层加文件只改那一层的 mtime。
真要跳过遍历得读 USN 日志（要管理员）或常驻监听，都碰"免安装/不提权"的边界。
实测（vite 478 目录）：冷跑 478 读 / 61ms，热跑 478 复用 / 0 读 / 40ms。

## 为什么

实测（SSD）：`D:\projects` 深度 4 一共 3,680 个目录、**287 ms**——**慢不是主因**。
真问题是判定烧进遍历之后：规则一改就得重扫、"为什么跳过它"没有记录、monorepo 里的子项目被 `return` 吃掉。

## 不适用

- 只扫**一层**、且项目数很少的场合（一次性遍历更简单）；
- 需要"实时反映磁盘"的场景——索引必须配增量，否则会撒谎。

## 守卫

`索引与_discover_对同一棵树给出同样的项目集` · `跳过的目录要留一行并且说清原因` · `第二次建索引时事实全部复用`（crates/engine/src/understand/dirs_index.rs）
