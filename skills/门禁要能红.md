# 门禁要能红

## 判据

一条判据合格，要同时满足：

1. 说得出**它什么时候会红**（具体的坏输入，不是"注意别写错"）；
2. **负向验证过**：把要守的东西弄坏 → 红 → 复原 → 绿；
3. 失败时给**原始输出**，不是一句"检查未通过"。

## 为什么

- 「表格里写着三条，机器上只守住一条」——`Conclusion` 零调用却当抓手守了十五轮。
- `l == "Rust"`、`"C/C++" vs "C / C++"`：两条**永远不成立**的比较，门禁一直是绿的。
- 修正器自己也会坏：`check-toolchains` 的自测就是为了证明"校验器本身会红"。

## 不适用

- **一次性探查**（临时脚本看个数）不需要门禁；
- 判据本身还没稳定的**探索期**——先量清楚再固化成门禁，否则会把误报固化。

## 守卫

`check-toolchains.mjs --selftest`（10 条自测）· `fetch-toolchain.mjs --selftest`（5 条）· `checkRunMissingWiring`（gate.mjs）
